# AP UserDocs v1.5: screens first, then the sentences

> **Status: approved 2026-09-02, in execution.** Supersedes v1.4 by correcting
> two endpoint names v1.3 chose without checking the API's own reservations.
> Everything else is v1.3's plan with v1.4's decisions.

## Corrections

1. **Per-user preference endpoint.** v1.3 put it at `GET/POST
   /settings/personal-options`. AP RuleBands (v1.0–v1.2, 2026-08-24) reserved
   **`/api/v1/preferences/{key}`** — "namespace reserved; first tenant: Feature
   5's drift-notification opt-out" — as part of the public API. Block 3 uses
   it: `GET /api/v1/preferences/{key}` and `PUT /api/v1/preferences/{key}`, the
   preferred algorithm being the first key, documented in `api-v1.md` and the
   OpenAPI spec like every other v1 endpoint.
2. **Instance-wide settings endpoint.** `GET /settings/admin-options` and `POST
   /settings/admin-options/save` become one resource, **`GET /settings/global`**
   and **`PUT /settings/global`**. The PUT changes only the fields sent — the
   admin page now has two sections saving to it, and a section must be able to
   save its own part without resetting the other's to defaults it never showed.
   Done in Block 1, since the allowlist is that second section.

Neither endpoint was in the OpenAPI spec (the `/settings/*` surface is
UI-internal by decision, UserDocs v1.0), so the rename breaks no documented
client. The e2e support helper and the admin page follow.
