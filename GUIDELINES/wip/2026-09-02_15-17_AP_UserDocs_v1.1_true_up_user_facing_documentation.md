# AP UserDocs v1.1: true up user-facing documentation

> **Status: preliminary — not yet approved.** Supersedes v1.0 (2026-08-29), whose
> findings were re-verified against HEAD one by one: **nine of them are already
> fixed**, overtaken by the doc sweeps in the RuleBands and KeyNamespace cycles.
> Only Block 1 touches shipped code and needs a CHANGELOG bullet.

## Discussion

v1.0 was written against a tree five days and three cycles old. Re-checking each
finding rather than trusting the list is most of what this revision is.

**Already fixed, dropped from the plan:** the `/ocs/v2.php` prefix (every URL in
`docs/api-v1.md` and the OpenAPI `servers` entry now carries it), `min_count` →
`minCount`, the `appinfo/info.xml` link to the renamed `docs/user-guide.md`, the
"rule management is not exposed" sentence, the two broken relative links, the
stale-vocabulary sweep, the `mode` column help, and both OpenAPI response
shapes. That last one included a **code** ticket v1.0 raised at its gate rather
than planning: `RulesController::create()` now returns
`findRuleById( $id )`, so a POST caller does receive the new rule's id, and the
spec documents it.

What survives is concentrated in three places: in-UI help text still describing
the pre-selector model, `docs/api-v1.md`'s error and signature claims, and a
handful of additions the docs never got.

## Analysis

Each item below was checked against HEAD (`4a1f01b`) at the line cited.

### A. In-UI help — shipped, user-visible, wrong

| Where | Now | Why wrong |
|---|---|---|
| `src/rules-vue/RuleTable.vue:87` `COLUMN_HELP.scope` | `'"All users" for everyone on this instance, "Group: <name>" …, or a single user's ID'` | Describes the retired model. "All users" is not a rendered scope value, and three of the six selector kinds — every home folder, one group folder, one storage — are missing entirely. |
| `src/rules-vue/RuleTable.vue:102` `COLUMN_HELP.enforced` | `'Enforced rules fill the first three bands'` | There are **four** enforced bands (`bands.ts:30-38`). |
| `src/` icon-only controls | 5 `aria-label`s in the whole tree (2 in `RuleRow.vue`, 2 in `DocsViewer.vue`, 1 in `HelpPopover.vue`) | The drag handle, help-popover triggers, banner close and status refresh carry no accessible name. |

The scope text should be written from what `selectorLabel()` actually renders
(`src/rules-vue/bands.ts:107-129`) rather than from the model.

### B. `docs/api-v1.md` — claims that are false

| Line | Claim | Actual |
|---|---|---|
| `:70`, `:94`, `:218` | `findByHash`, `getHashesByFileId`, `recalcHash` signatures | All three take `?string $requestingUser = null` (`ChecksumApi.php:195-200, 86-89, 372-375`). Omitting it hides the trusted-caller semantics: `null` means server-side authority. |
| `:162` | "Find all duplicate hash groups across the entire system" | Per-user. `findDuplicates` resolves the session uid and calls `listDuplicatesForUser` (`ChecksumApi.php:264`); a session-less caller gets an empty set. |
| `:234` | `'File not found: 99999'` | `'File not found.'` (`HashCalculationService.php:876`, `ChecksumApi.php:382`). |
| `:707` | "All API endpoints use `#[NoCSRFRequired]`" | False for the four rules mutations and two settings POSTs. It is the `OCS-APIRequest: true` header that carries a cookie-session mutation past CSRF; with basic auth it is optional. |
| `:815-821` | Status table: 200/400/404/429/500 | Omits **401** (getHashes, lookup, recalc, apply) and **403**. |
| `:834-840` | "All Error Responses Follow the Same Shape — `{"error": …}`" | The rules endpoints and recalc answer `{success: false, error: …}`. Both shapes need stating. |

### C. `docs/api-v1-openapi.yaml`

- `HashEntry` is `required: [algo, hash]` with only those two properties; the
  code also emits `updated_at` (`ChecksumApi.php:105-110`), which
  `api-v1.md:352` already shows.
- `RuleInput` declares `required: [path]`, which is not enforced — an absent
  path defaults to `/` (`RuleDefinitionValidator.php:68`).
- **Not re-verified:** v1.0's status-code findings (lookup/file-duplicates 404s,
  recalc's 400-not-404, all-duplicates 400) and the tag-casing item. They are
  in the plan as *check, then fix if still true* rather than as fixes, because I
  did not confirm them and will not carry an unverified claim forward.

### D. Root `openapi.json`

The untouched Nextcloud skeleton stub: version `0.0.1`, one invented
`api-index` path, none of the twelve real endpoints. Excluded from the package
(`.nc.publish.ignore:53`) but tracked, and the first file a reader looks in.
`git rm` it; `docs/api-v1-openapi.yaml` is the maintained spec, and regenerating
a real one is out of scope.

### E. README / FAQ — true things not said

- **Default-shaped paths.** The docs say the defaults partition is the bare `**`
  rule; the code also treats `''` and `'/'` as default-shaped
  (`RuleService.php:371-383`). One clause in README "Defaults, and what is not
  covered" and in the FAQ rules answer.
- **Status-page rows.** The FAQ's troubleshooting answer names none of the row
  labels an operator actually reads — 0 occurrences of *Untrusted Hashes* or
  *Status Info*. (v1.0 said *Eroded Hashes*; the row was renamed when erosion
  and reset were folded into one untrusted total, so v1.0's own wording was
  stale.)
- **Coverage rows.** One passing mention of "not covered" in the README. The
  rules chapter should spend two sentences on the virtual rows and their
  *Create rule* button, since that is now the guided path to a first scoped
  rule.

### F. `CONTRIBUTING.md`

Nine `.aiassistant/` references to a tree that became root `AGENTS.md` +
`GUIDELINES/shared/`. Each needs its canonical successor; the `tools/phpunit`
paths must be checked against `GUIDELINES/shared/tools/` for their real names.

### Recorded, not planned

Only `src/sidebar-vue/*` and `src/sidebar.ts` call `t()`; there is no `l10n/`.
Every string this AP touches is untranslated. The fix pass should **not** wrap
them — one mechanism later, not two vocabularies — but should keep new strings
short and self-contained so the later sweep is mechanical.
