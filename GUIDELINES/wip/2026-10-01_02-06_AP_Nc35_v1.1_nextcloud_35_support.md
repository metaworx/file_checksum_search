# AP Nc35 v1.1: Nextcloud 35 support

## Discussion

- **The ask.** The user, 2026-09-30: support Nextcloud 35.
- **Not scheduled.** It is a brief plan.
- **Rector as the upgrade tool** (the user, 2026-10-01). It is installed
  here, where it is first used, and only for upgrades: Nextcloud's own
  rules for deprecated OCP APIs. It gets no general rule sets and no CI
  step. ECS keeps the style and Psalm the types. A later upgrade, such as
  PHPUnit 11 or a higher PHP floor, uses the same installation with its
  own set.

## Analysis

**Today:**
- `appinfo/info.xml` declares Nextcloud 33 to 34 (`max-version="34"`).
- CI's PHPUnit and Cypress matrices test `stable33` and `stable34`.
- The harness already runs Nextcloud 35.0.1 (instance 35), whose
  `3rdparty/autoload.php` and `lib/composer/autoload.php` are there for a
  tool to load.

**Rector, as found on 2026-10-01:**
- Not installed. The `rector.php` the app skeleton brought does not load
  on Rector 2: it names the `strictBooleans` set, which Rector 2 removed.
- A dry run of its other sets (Rector 2.6.7, from a scratch install) would
  rewrite 124 files. Some of it is damage:
  - it removes `parent::setUp()` from `DatabaseTestCase` and the
    integration tests, because without the server's autoloaders it
    cannot see the parent classes;
  - it removes `RepairQuietStart`'s steps and some test helpers as unused,
    because it cannot see the method table that reaches them.
- `nextcloud/rector` (v0.5.2 on 2026-10-01) carries Nextcloud's upgrade
  rules. Which of its sets reach 35 is read from the package when it is
  installed.

**Unknown until measured:**
- whether the unit, integration and e2e suites pass on 35;
- what Nextcloud 35 deprecated or removed among the OCP interfaces and
  events the app uses, per its developer manual's upgrade notes, and what
  `nextcloud/rector`'s sets rewrite for it;
- whether `@nextcloud/vue` and the other frontend libraries need a newer
  version for 35.

## Implementation Plan

0. **Rector, for upgrades.**
   - `vendor-bin/rector/composer.json`: `rector/rector ^2.6` and
     `nextcloud/rector`, with the PHP platform 8.2.27 like Psalm's.
     Install it with `composer bin rector install`, and commit the lock.
   - `rector.php` replaced: paths `lib/` and `tests/`, and
     `withBootstrapFiles()` loading the server's autoloaders from where
     `tests/bootstrap.php` finds a server (the server the app sits in, a
     `nextcloud-v*` tree beside it, or `FCIAS_NC_ROOT`), never
     `lib/base.php`. The only sets are Nextcloud's upgrade sets, up to 35.
   - `composer.json`: `rector` loses its `&& composer cs:fix` (ECS runs
     after, by hand, like after any edit), and `rector:check` runs
     `rector --dry-run`.

   **Verification:** `composer rector:check` runs in the harness container
   with no system errors.
1. **Measure.**
   - Run the PHPUnit suites and the e2e specs on instance 35.
   - Read the upgrade notes against the app's use of OCP.
   - Run `composer rector:check` with the Nextcloud sets.

   Write down what fails and what Rector would rewrite.
2. **Fix** what fails, each defect as a commit of its own with its tests,
   while 33 and 34 keep passing. Where Rector's rewrite is the fix, it is
   applied with `composer rector`, and the diff is reviewed like any
   other.
3. **Declare it.**
   - `max-version="35"` in `appinfo/info.xml`;
   - `stable35` in CI's PHPUnit and Cypress matrices;
   - the README's supported versions;
   - a CHANGELOG bullet.

**Verification:** every suite on 33, 34 and 35; the manifest schema;
`composer psalm` and `composer cs:check`.
