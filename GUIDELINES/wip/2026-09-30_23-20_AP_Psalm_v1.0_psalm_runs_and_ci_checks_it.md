# AP Psalm v1.0: Psalm runs, and CI checks it

> **Status: proposal, 2026-09-30.** The contract's lint row names
> `composer psalm`, but the command has never run here: Psalm is not
> installed, and CI does not run it.

## Discussion

Decided with the user, 2026-09-30:

- **Integrate Psalm**, starting at a level the code can pass without a
  baseline, and tighten it later.
- **The crash Psalm found** in `occ file-checksum-search:hash-files` is
  fixed on its own, ahead of this plan and outside it: it is a shipped bug.

Proposed here, open at the gate:

- **Level 4, no baseline.** A baseline hides every finding it records,
  and at level 1 that would be 854 of them. Level 4 leaves 188 findings,
  which this plan clears.
- **No unused-code check (`findUnusedCode="false"`).** Psalm cannot see
  how Nextcloud reaches a class: commands through `info.xml`, controllers
  through routes, settings through `info.xml`, repair steps through a
  method table. Every command, controller and settings class is reported
  as unused (26), and every repair step as an unused private method (11).

## Analysis

1. **The trial run.** Psalm 6.19.1, as a phar in the scratchpad, over
   `lib/` with the checkout's `vendor/`. Errors without the unused-code
   check:

   | Level | Errors |
   |---|---|
   | 1 (as `psalm.xml` has it, with the unused-code check) | 854 |
   | 2 | 378 |
   | 3 | 246 |
   | 4 | 188 |
   | 5 | 172 |

2. **What level 4 reports:**
   - **84 × `MissingOverrideAttribute`.** Mechanical: `psalter
     --issues=MissingOverrideAttribute` adds `#[\Override]`.
   - **34 × classes outside the public API** (`MissingDependency`,
     `UndefinedClass`, `UndefinedDocblockClass`):
     - `OC\Files\Search\SearchQuery` and `SearchComparison` in
       `RuleService` (line 1761);
     - `OC\FilesMetadata\FilesMetadataManager` in `RepairQuietStart`;
     - `OC\FilesMetadata\Model\FilesMetadata` in `MetadataService`;
     - `Doctrine\DBAL\*` through `IDBConnection::getInner()` in
       `DatabaseService` and one migration;
     - `OC\User\NoUserException` in docblocks in `FilecacheService`;
     - `OC\Hooks\Emitter`, which `OCP\Files\IRootFolder` extends in the
       OCP package but which ships only with the server.

     Each use is deliberate. Each is also a risk for Nextcloud 35
     (AP Nc35), so it is suppressed by name, with the reason beside it.
   - **About 70 real type findings.** Most are docblock return shapes that
     no longer say what the code returns:
     - `ChecksumApi::getStatus()` and `getHashesByFileId()`;
     - `HashIndexService::listDuplicatesForUser()` and `findByHash()`;
     - `AppConfigService::import()`;
     - `DatabaseService::getInstalledMigrations()`;
     - `MetadataService::parseQueryTerm()`;
     - the `withLocations()` parameter;
     - `FindDuplicates::writeOutput()`, which lacks
       `match_count`/`mismatch_count`.

     Seven functions can return `false` where they declare a string or a
     resource: `hash_file()` in `computeSingleHash()`, `json_encode()` in
     `JsonFormat::encode()`, `file_get_contents()` in the two
     `readRequestBody()`, `AppConfigService::read()`, and `fopen()` in
     `Backup::openOutput()` and `Import::openInput()`. Under
     `strict_types`, each is a `TypeError` where the code meant to report
     an error.

     A few more:
     - `ParadoxicalCondition` × 2 in `SudoScope`: dead conditions after an
       early return;
     - `InvalidOperand` × 4 in `TestPerformance`: int/float mixing;
     - `UndefinedInterfaceMethod` for `OutputInterface::getErrorOutput()`
       in `DatabaseService` and `HelperInterface::ask()` in `DeleteRule`,
       which exist on the concrete classes and need a type check or a
       narrower type.
3. **Installation.** The app already keeps tools in `vendor-bin/<tool>/`
   (ECS, PHPUnit, the OpenAPI extractor) through
   `bamarni/composer-bin-plugin`. Psalm 6 needs PHP 8.2 or later, which is
   the app's floor. `psalm.xml` says `phpVersion="8.1"`, which is stale.
4. **CI.** `test.yml`'s Lint job runs `composer lint` (`php -l` only) and
   never runs `composer install`, so ECS does not run there either. A
   Psalm step needs `composer install` first, which brings in ECS too.
   Adding `composer cs:check` to that job costs one line; it is proposed
   here as optional.
5. **Nextcloud versions.** `nextcloud/ocp` is `dev-stable33`, the lowest
   supported version. Nextcloud's own template runs Psalm once per OCP
   version. One run, against the lowest, is proposed. A matrix would add
   a job per version for API differences the e2e matrix already catches.

## Implementation Plan

### Block 1: installation and configuration

1. `vendor-bin/psalm/composer.json`: `vimeo/psalm ^6`, with the platform
   set to PHP 8.2 like the other tools. Then `composer bin psalm install`,
   and commit its `composer.lock`.
2. `psalm.xml`:
   - `phpVersion="8.2"`, `errorLevel="4"`, `findUnusedCode="false"`,
     `findUnusedBaselineEntry` dropped;
   - an `<issueHandlers>` block that suppresses each non-public class of
     Analysis 2 by its name (`referencedClass`), with a comment naming the
     class's use and AP Nc35;
   - `vendor` stays in `extraFiles`.
3. `composer psalm` runs from the checkout and in the container.

**Verification:** `composer psalm` runs and reports the level-4 findings
less the suppressed ones.

### Block 2: `#[\Override]`

1. `vendor/bin/psalm --alter --issues=MissingOverrideAttribute`, then
   `composer cs:fix` over the files it touched.

**Verification:** no `MissingOverrideAttribute`; `composer cs:check`;
phpunit `unit`.

### Block 3: the type findings

1. **Docblock shapes** (Analysis 2): each made to say what the code
   returns. The code does not change.
2. **Falsable returns:** each `false` handled where it arises:
   - `computeSingleHash()` throws with the file named;
   - the `readRequestBody()` pair returns `''`;
   - `JsonFormat::encode()` uses `JSON_THROW_ON_ERROR`;
   - `openOutput()`/`openInput()` report the path;
   - `AppConfigService::read()` falls back as its callers expect.

   Each gets a unit test where one does not exist.
3. **The rest:**
   - `SudoScope`: the dead conditions go, the early return staying the
     one check;
   - `TestPerformance`: explicit casts;
   - `DatabaseService`: `getErrorOutput()` behind an
     `instanceof ConsoleOutputInterface`;
   - `DeleteRule`: `QuestionHelper` by type.

**Verification:** `composer psalm` reports nothing; `composer cs:check`;
phpunit `unit` and `integration` on harness instance 34.

### Block 4: CI and the contract

1. `.github/workflows/test.yml`, Lint job: `composer install` (with
   PHP 8.2 set up), then `composer psalm -- --no-progress
   --output-format=github`. Optionally `composer cs:check` beside it
   (Analysis 4).
2. `GUIDELINES/project/_CONTRACT.md`, lint row: `composer psalm` at
   level 4, and CI runs it. Then `sync-docs.sh` regenerates `AGENTS.md`
   and `GUIDELINES/README.md`.
3. `CONTRIBUTING.md`: `composer psalm` says what it checks, if the text
   there needs it.

**Verification:** the workflow parses; the Lint job passes on the pushed
branch; `sync-docs.sh --check`.

Not in scope:
- Levels 3 to 1, which are follow-ups once level 4 holds.
- Replacing the non-public classes, which is AP Nc35's decision.
- Psalm over `tests/`.

CHANGELOG: Blocks 1, 2 and 4 are tooling (`vendor-bin/`, `psalm.xml`,
`.github/`, `GUIDELINES/`), exempt under COMMIT.md §5.1. Block 3 changes
shipped code and gets a bullet under `### Fixed`, for the falsable
returns that became a `TypeError`.
