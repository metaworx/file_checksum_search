# AP LocalPath v1.0: absolute path in findByHash

> **Status: proposal, 2026-09-24.** Written for the handover
> *localPath in findByHash* v1.0 and the evaluation of it (both in
> `messages/`, so neither is cited from here). The maintainer decided the
> path is **absolute**; the other choices the handover left open are
> settled below and listed under *Open decisions* so the gate can undo
> them.

## Discussion

kunstarchiv moves its `FallbackFileFinder` onto this app: one
`findByHash()` replaces a filename search plus a hash read per candidate.
A hit is written into a column that holds paths of its own, and the one
shape it can take without guessing is an absolute filesystem path. It has
two implementations planned, a native one (`Server::get(ChecksumApi::class)`
after bootstrapping `lib/base.php`) and a REST one against
`GET /api/v1/lookup`, so both surfaces are decided here.

## Analysis

1. **Nothing returned today is a filesystem path.** Unscoped, `path` is
   the filecache path, `files/Fotos/x.jpg`; scoped, it is the user
   folder's relative path from whichever account in reach opened it
   first. `location` is `FileLocation::describe()`: right for a home
   file, a selector for everything else, and documented as prose for
   log lines.
2. **There is one place to resolve it.** Both branches of
   `ChecksumApi::findByHash()` end in
   `FilecacheService::batchLookupFilecachePaths()`: the unscoped one
   through `DuplicateService::findByHash()`, the scoped one through
   `withLocations()`. Each row there has its storage id and internal
   path, wrapped in a `FileLocation`.
3. **The storage id says where a local storage lives.** `home::<uid>` is
   a `Local` storage rooted at `IUser::getHome()`; `local::<root>` is
   rooted at `<root>`, which covers an external local mount and a
   current-layout group folder (`local::<datadir>/__groupfolders/<id>/`);
   the legacy layout is a `local::<datadir>/` root with
   `__groupfolders/<id>/…` inside it, which the same rule covers.
   `object::`, `shared::`, `smb::`, `webdav::` and the rest have no local
   file. Deriving the path from the id needs no storage object, no mount
   lookup and no disk access, which is what a batch of rows wants;
   `getLocalFile()` would need an `IStorage` per row and resolves
   symlinks, which a consumer mapping paths does not want.
4. **Server-side encryption.** The encryption wrapper answers
   `isLocal()` false while enabled, and the file on disk is a blob. The
   field is `null` on an encrypted instance, decided by
   `OCP\Encryption\IManager::isEnabled()`, so the consumer's fallback
   fires rather than reading ciphertext.
5. **Rights belong to the REST layer.** The native API carries no caller;
   `$reachUids` is a reach, not a permission, and an in-process caller
   can read the data directory anyway. So the API gets a flag and the
   controller decides who may set it: sudoers, on `/api/v1/sudo/lookup`
   only. A group leader who asks is refused, not silently given less.
6. **Found on the way.** `occ file-checksum-search:search` prints
   `files/…/a.txt/a.txt`: it appends `name` to a `path` that already ends
   in it. `docs/api-v1.md` and the OpenAPI file describe `path` as the
   folder for the same reason.
7. **Release.** An added field under the pre-1.0 rule is a minor bump;
   `[Unreleased]` already holds the session's work, so the cut is
   0.20.0 either way. It is the last block, on the maintainer's word.

## Implementation Plan

1. **[FIX] The search command and the documents say what `path` is.**
   `SearchHash` prints `path` alone. `docs/api-v1.md` (the `findByHash()`
   example and prose, the REST example) and `docs/api-v1-openapi.yaml`
   (`HashLookupResult.path`) say the path includes the name, with an
   example that does. CHANGELOG: a Fixed bullet for the command; the
   documents are not shipped code.
   **Verification:** PHP unit suite; `occ file-checksum-search:search`
   on the instance prints each path once.

2. **[FEATURE] A local path on every located row, when asked.**
   `FileLocation` gains `localPath( ?string $homeDir ): ?string`, pure:
   `home::` with a home dir → `<home>/<internalPath>`; `local::<root>` →
   `<root>/<internalPath>` (with or without the id's trailing slash);
   anything else `null`. `FilecacheService::batchLookupFilecachePaths()`
   takes `bool $withLocalPath = false`, gets `IUserManager` and
   `OCP\Encryption\IManager` injected, and when asked adds `local_path`
   to each row: `null` while encryption is enabled, else the derivation
   with the owner's home looked up once per uid.
   `HashIndexService::batchLookupFilecachePaths()` and
   `findByHash()`, and `DuplicateService::findByHash()`, pass the flag
   down, and the unscoped row gains `local_path` beside `location`.
   Tests: `FileLocationTest` for the derivation (home, external local
   mount, both group-folder layouts, object store, share);
   `FilecacheServiceTest` for the flag, the encryption null and the
   per-uid lookup; `DuplicateServiceTest` for the pass-through.
   CHANGELOG: none yet, the field is not reachable until block 3.
   **Verification:** PHP unit suite; psalm; `cs:check`.

3. **[FEATURE] `findByHash()` returns `localPath`, and the sudo route
   exposes it.** `ChecksumApi::findByHash()` takes
   `bool $withLocalPath = false` as its fifth parameter; with it each
   row has `localPath: ?string`, without it the key is absent, so the
   shape does not change for anyone. Both branches pass it to the batch
   lookup. `PublicApiController::sudoLookup()` takes `bool $localPath =
   false` (`?localPath=1`); when set and the caller is not
   `SudoScope::isSudoer()`, 403 `Not yours to look at.`; `lookup()` has
   no such parameter. `docs/api-v1.md` (method reference, endpoint 17,
   the cross-account table) and the OpenAPI file (the parameter on
   `/api/v1/sudo/lookup`, `localPath` on `HashLookupResult`) describe
   it, including that it is `null` on a non-local storage and on an
   encrypted instance. `SearchHash` gets `--local-path`, printing the
   field after the path. CHANGELOG: one Added bullet.
   Tests: `ChecksumApiTest` (field present with the flag in both
   branches, absent without); `PublicApiControllerTest` (sudoer gets
   it, a leader is refused, the ordinary route ignores it);
   `SearchHashTest` if one exists, else the command by hand.
   **Verification:** PHP unit suite; psalm; `cs:check`; on the instance,
   `occ file-checksum-search:search --local-path` for a home file and a
   group-folder file (the jail question: the group folder's path must be
   `<datadir>/__groupfolders/<id>/…`), and an administrator's
   `GET /api/v1/sudo/lookup?hash=…&localPath=1` with an app password.

4. **[RELEASE] 0.20.0.** `changelog.sh cut 0.20.0` after the pending
   commits of this session (the e2e flake fix, the manifest check in CI)
   are in; the manifest, the four `RELEASE-PIN` blocks and `<version>`
   move together. Only on the maintainer's word at its own gate.
   **Verification:** `changelog.sh check`; `xmllint` against the store's
   `info.xsd`; `composer test`; `npm test`.

## Open decisions

- **Encryption → `null`** (analysis 4). The alternative is the path of
  the encrypted file, which is a real path but not the file's content.
- **A leader asking for `localPath` is refused with 403** (analysis 5).
  The alternative is to answer without the field, which a caller would
  have to notice.
- **`--local-path` on the occ command** is convenience for the live
  check as much as a feature; drop it if unwanted.
