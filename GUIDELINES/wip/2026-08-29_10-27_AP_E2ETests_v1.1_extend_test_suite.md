## Discussion

- **CI is failing now, not at release time.** `.github/workflows/test.yml:190-199`
  (`integration-chrome`, `cypress-io/github-action@v6`, `spec: tests/e2e/**/*.cy.js`) runs on every
  matrix push. Full live run against instance 34 (2026-08-29, Electron 138, Cypress 15.20.0, one
  spec per run):

  | Spec | Result | Time |
  |---|---|---|
  | `app-enable.cy.js` | 2/2 pass | 1:55 |
  | `checksums.cy.js` | 3/3 pass | 1:15 |
  | `duplicates.cy.js` | **2/3** — "verifies hashes" fails | 1:58 |
  | `global-search.cy.js` | 1/1 pass | 0:31 |
  | `rules.cy.js` | **0/4 fail** (60 s timeout each) | 5:30 |

- **Two failures, two different diseases.** `rules.cy.js` asserts a UI and an API that no longer
  exist (rewrite, not repair). `duplicates.cy.js` fails from **test rot**: every run uploads the
  same `dupContent`, the sha1 group has accumulated 145 files on the instance, and Verify hashes
  hits the per-user 429 rate limit partway ("Verification stopped: too many recalculation
  requests…", the rate-limit-aware verify at src/duplicates-vue/composables/useDuplicates.ts:101-110
  postdates the spec). That also falsifies `tests/e2e/README.md:117-120`'s claim that repeated
  local runs "simply accumulate files rather than collide" — the accumulation is exactly what
  kills it.
- **No state reset exists anywhere** in `tests/e2e/support/e2e.js` — no rule reset, no appconfig
  reset (`idle_banner_ack`), no uploaded-file cleanup. That absence is what rotted the duplicates
  spec, and it is the single highest-value missing helper; it is therefore a **prerequisite block**
  here, ahead of every new spec.
- **Text-free selectors are a hard requirement.** Only `src/sidebar-vue/*` and `src/sidebar.ts`
  use `t()`; there is no `l10n/` directory yet. When translation lands, every
  `cy.contains('Enable')`-style assertion breaks — and the rules failure shows how brittle literals
  are even without i18n (see below). New specs assert on `data-*` attributes, ids and API payload
  fields, never on visible app strings; the one exception is untranslated Nextcloud-core chrome
  (login page, apps list).
- **API ground truth, verified by probe:** the app's endpoints answer **only** at
  `/ocs/v2.php/apps/file_checksum_search/...` (`/index.php/apps/...` and `/apps/...` are 404), the
  body is **plain JSON with no `{ocs:{…}}` wrapper** (controllers extend `ApiController`, not
  `OCSController`), and with basic auth the `OCS-APIRequest: true` header is **not** required
  (200 without it) — send it anyway for uniformity with cookie-session calls, where it is.
- **Runner environment:** chrome is not installed for Cypress locally — electron is (CI uses
  chrome). From a sandboxed shell, hostname resolution for the ddev URL fails even with a correct
  `/etc/hosts`; Cypress then needs
  `ELECTRON_EXTRA_LAUNCH_ARGS='--host-resolver-rules=MAP nextcloud-34.ddev.site 127.0.0.1'`.
  A normal user shell should not.

### Block 1 — prerequisite: state reset + support commands

1. In `tests/e2e/support/e2e.js` add (names final, bodies illustrative):

```js
// Reset the rule set to the shipped state: delete everything, let the repair
// step recreate the two disabled defaults, and drop the banner ack. occ is
// the only honest reset — REST refuses some mutations by permission design.
Cypress.Commands.add( 'fciasResetRules', ( occ ) => {
	cy.exec( `${ occ } fcias:rules:list -o json`, { failOnNonZeroExit: false } )
		.then( ( { stdout } ) => {
			let rules = []
			try { rules = JSON.parse( stdout ) } catch ( e ) { /* not JSON: empty */ }
			for ( const rule of rules ) {
				cy.exec( `${ occ } fcias:rules:delete ${ rule.id } -y`, { failOnNonZeroExit: false } )
			}
		} )
	cy.exec( `${ occ } config:app:delete file_checksum_search idle_banner_ack`,
		{ failOnNonZeroExit: false } )
	cy.exec( `${ occ } maintenance:repair` )
} )

// Authenticated request to the app's API. Endpoints exist only under
// /ocs/v2.php (verified); the body is plain JSON, no ocs wrapper.
Cypress.Commands.add( 'ocs', ( { method = 'GET', url, body, user, password, failOnStatusCode = false } ) => {
	return cy.request( {
		method,
		url: `/ocs/v2.php/apps/file_checksum_search${ url }`,
		body,
		auth: { user, pass: password },
		headers: { 'OCS-APIRequest': 'true', Accept: 'application/json' },
		failOnStatusCode,
	} )
} )

// Ensure alice and bob exist (CI starts with only admin).
Cypress.Commands.add( 'fciasEnsureUsers', ( occ ) => {
	for ( const u of [ 'alice', 'bob' ] ) {
		cy.exec( `OC_PASS=SecretPass123! ${ occ } user:add --password-from-env ${ u }`,
			{ failOnNonZeroExit: false } )
	}
} )
```
