# AP AdminTabs v1.0: permissions, status, and the listing that never loaded

> **Status: proposal, 2026-09-03.** From the user's review of the admin and
> personal pages after SudoMode (e6c427b). Two bugs, one unreadable colour,
> one misplaced icon, and a reshaping of the admin page into tabs.

## Findings

1. **The token listings never loaded from the browser.** Every GET route
   this app serves to its own pages carries `#[NoCSRFRequired]`; the two in
   `SudoTokensController` (`mine`, `all`) do not, and both pages fetch them
   with a bare `fetch()` — no `requesttoken` header — so core's CSRF check
   refuses them. The admin tab answers with *the token table could not be
   read*, which is untrue: the request never reached the app. The personal
   section fails silently and shows *No app passwords yet* to a user who
   has some. Neither route is covered by any test that runs in a browser or
   over HTTP; the routes answer 200 to curl with Basic auth, which is how
   the gap survived.
2. **`.fcias-error` uses `--color-error`**, the *background* red of core's
   palette, unreadable on the dark theme. Text wants `--color-error-text`.
   Two stylesheets, `settings-admin.css` and `sidebar.css`.
3. **The help icon inside `<h4>Sudo tokens</h4>`** is `display: flex` — a
   block box in a block heading, so it drops onto its own line under the
   title, with the heading's rule under it. The preferred-algorithm select
   had the same shape of problem until its row became a flex container.
4. **Tabs.** Documentation must stay last, and it is not. Four permission
   sections sit between the algorithms and the rules of one long Settings
   tab, one of them titled differently from the other three. The status
   table, read-only diagnostics that grow with every job, heads the same
   tab.

## Rulings folded in

- Documentation is the last tab, and stays so: a note in the component.
- A **Permissions** tab before *Sudo tokens*, holding all four sections,
  every heading of the form *Who may …*: *Who may calculate by hand*
  (renamed from *recalculate* — the permission is about computing, not
  about doing it again), *Who may edit rules* (from *Rule Editing
  Permission*), *Who may look across accounts*, *Who may use the API*.
  Switch labels follow: *Allow all users to …*. The config keys do not
  change. The API's refusal text follows the heading: *This account may
  not calculate by hand.*
- **Status** becomes its own tab before Documentation — recommended, and
  built unless struck: diagnostics and configuration are different pages
  to different readers, and the Settings tab is then what its name says,
  algorithms and rules.

Tab order: **Settings · Permissions · Sudo tokens · Status · Documentation**,
hashes `#settings #permissions #tokens #status #docs`.

## Blocks

1. **[FIX] Token listings, from the browser.** Both GET fetches send the
   request token, as every write in the app already does — the CSRF check
   is kept, not waived. The pages then say what actually happened: an
   HTTP failure names its status; only a listing the server marks
   `available: false` says the token table could not be read, which
   `AuthTokenRepository` now reports instead of swallowing into an empty
   list. Personal section: a failed load is a line of its own, not *No app
   passwords yet*. Tests: the two unit specs learn the header and the
   two messages; a new e2e spec `sudo-tokens.cy.js` covers what had none —
   the admin tab shows *No grants* (not the error), a user with an app
   password minted by occ sees it listed and grants it (core's
   confirmation dialog is skipped within thirty minutes of login, which a
   Cypress session always is), the admin tab lists the grant and revokes
   it.
2. **[FIX] Readable errors, and a help icon that stays on its line.**
   `--color-error-text`; the icon `inline-flex`.
3. **[TASK] The Permissions tab.** Four sections moved, retitled, ordered
   as ruled; `PermissionSection` untouched. *recalculate* → *calculate* in
   the heading, the switch, the help text, the API's refusal string, the
   OpenAPI and prose docs, and the Unreleased CHANGELOG bullet (net-effect
   rule). Tab type and hash handling extended; the docs tab keeps its
   note.
4. **[TASK] The Status tab.** The status table, its Refresh, and the idle
   banner's home: the banner stays on Settings, where the rule it points
   at is. `status.cy.js` opens the tab (`#status`) before reading its
   cells.
5. **Docs and the full suite.** README's admin-page section, FAQ, user
   guide; full e2e.

## Gate

Per block: PHP suite, `npm run lint`, `npx vitest run`, `npm run build`,
the e2e specs the block touches (`sudo-tokens`, `rules-admin`, `status`,
`rules-personal`); full e2e at the end.

## Open decisions

1. Status as its own tab — built as recommended unless struck.
2. The order of the four permission sections: as listed above (the
   user's order) unless another is preferred.
