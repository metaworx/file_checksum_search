# AP JobRuns v1.0: run outcome and execution mode

## Discussion

- **Origin.** Carried over from AP SuggestedFeatures v1.5 (2026-08-22), at
  the user's request of 2026-09-30: its run-history and execution-mode
  feature, less what is built.
- **Not scheduled.** It is re-confirmed with the user before it runs.

## Analysis

**Built:** each background job records when it last ran and a few counts
(`JobStatsService`), and `occ file-checksum-search:status` and the admin
status panel show them.

**Open, part one: a run's duration and outcome.** Record how long a run took,
and whether it ended normally or with an exception, beside the last run.

**Open, part two: the execution mode.** One of three modes:
- `cron.php`, Nextcloud's background jobs, which is today's only mode;
- custom cron only, where an administrator's own crontab entry calls the CLI;
- both.

The mode lets an administrator run the work outside Nextcloud's shared tick,
for example under `nice`/`ionice`, or on a schedule of their own.

**Three questions to answer with the user before part two is designed:**
- Is the mode per job, or one switch for all of them?
- Does "custom cron only" unregister the Nextcloud job, or leave it
  registered with `run()` doing nothing?
- How do "both" modes avoid working on the same files at the same moment?

**Constraints:**
- every new text is translatable, in every language kept here;
- `npm run typecheck` stays at zero errors.

## Implementation Plan

1. **Duration and outcome** in `JobStatsService`, shown where the last run
   is shown now. Tests: a run that ends normally and one that throws.
2. **The execution mode,** designed once the three questions are answered,
   and written into a new revision of this plan.

**Verification**, per block: its tests, the PHPUnit suites, Vitest,
`npm run typecheck`, ESLint and `scripts/l10n.sh check`.
