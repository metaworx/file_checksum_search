# AP DateLocale v1.0: dates in the user's locale

## Discussion

- The user, 2026-09-30: "[FIX] date format", after the British English
  review found that the app's dates follow the browser, not Nextcloud.

## Analysis

Four places format a date with `toLocaleString()` and no locale, so the
browser decides the format, not the locale the person chose in Nextcloud's
personal settings. All four were in v0.20.3:

- `src/settings-personal-vue/SudoTokensSection.vue`: a grant's last use;
- `src/settings-admin-vue/SudoTokensTab.vue`: the same, for administrators;
- `src/settings-admin-vue/App.vue`: a background job's last run;
- `src/settings-admin-vue/composables/useAdminSettings.ts`: "Last updated".

Nextcloud writes the user's locale to the page (`data-locale` on `<html>`);
`@nextcloud/l10n` reads it, falling back to the browser's only where the
page has none, and `getCanonicalLocale()` returns it as a BCP 47 tag
(`de_CH` → `de-CH`), as Nextcloud's own components pass it to `Intl`.
