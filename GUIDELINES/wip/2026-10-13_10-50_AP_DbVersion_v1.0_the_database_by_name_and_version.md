# AP DbVersion v1.0: The database by name and version

## TL;DR

The status's "Database version" is a raw `SELECT VERSION()`: "unknown" on
SQLite, and on MySQL a number that does not say which database it is.
It becomes the database's name and version, asked of each backend in its
own terms, and `occ fcias:status` shows it too. Most of `DatabaseService`
and two `StatusService` helpers have no caller; they go.

- `SELECT VERSION()` → `getDatabaseProvider(true)`, then `VERSION()` or
  `sqlite_version()`; the number cleaned out
- `10.11.6-MariaDB` / `8.0.39` / `PostgreSQL 16.4 on x86_64…` / `unknown`
  → `MariaDB 10.11.6`, `MySQL 8.0.39`, `PostgreSQL 16.4`, `SQLite 3.45.1`
- Panel, `GET /api/v1/status` (`dbVersion`), `occ fcias:status` (new line,
  `database_version`) → one string
- Unused → removed: `StatusService::getMigrationStatus()`,
  `hasChecksumColumn()`; `DatabaseService`'s schema, row-count and
  migration helpers
- FAQ: the claim that `occ fcias:status` shows the database version → true

## Discussion

Decided with the user, 2026-10-01 and 2026-10-13:

- **Name and server version**, not the app's migration state: Nextcloud's
  own `occ migrations:status file_checksum_search` answers that, and the
  app's migrations drift only after a failed upgrade.
- **Shown alike** in the panel, the API's admin status and `occ`.

Proposed here, open at the gate:

- **Per backend, public API only.** `IDBConnection::getDatabaseProvider(true)`
  (public since 28, `$strict` since 32) names the backend, MariaDB apart
  from MySQL; `SELECT sqlite_version()` on SQLite, `SELECT VERSION()`
  elsewhere — the serverinfo app's own choice. The alternative,
  `Connection::getServerVersion()`, is one call and no SQL, but sits on
  Nextcloud's private connection class and is marked `@internal`, "only
  inside the QueryBuilder".
- **The API's `dbVersion` changes form** with the panel's: from the server's
  own string to `<Name> <version>`. An admin-only diagnostic, documented as
  a string; the CHANGELOG says so.
- **The label stays "Database version"**: no text changes, no translations.

## Analysis

1. **Today** ([DatabaseService.php:64](../../lib/Service/DatabaseService.php)):
   `getRawConnection()->executeQuery('SELECT VERSION() AS version')`, any
   failure turned into `'unknown'` by `safeString()`.

   | Backend | `SELECT VERSION()` | Shown |
   |---|---|---|
   | MariaDB | `10.11.6-MariaDB-ubu2204` | as is |
   | MySQL | `8.0.39` | the number alone |
   | PostgreSQL | `PostgreSQL 16.4 on x86_64-pc-linux-gnu, compiled by …` | long |
   | SQLite | no such function | `unknown` |

   Oracle is not supported (no query is paid for it); it gets its name and
   "unknown".
2. **Nextcloud 33.0.8, 34.0.3, 35.0.1** (harness instances): Doctrine DBAL
   3.10.4 in each; `IDBConnection::PLATFORM_*` and `getDatabaseProvider()`
   identical; `getServerVersion()` only on `OC\DB\Connection` and its
   adapter, not on the interface.
3. **Callers** in `lib/`:
   - `DatabaseService`: `getDatabaseVersion()` alone is called (by
     `StatusService::getDbVersion()`). `columnExists()` and
     `getInstalledMigrations()` are called only by the two dead
     `StatusService` helpers; `countRows()`, `tableExist()`,
     `getSchemaManager()` and `getRawConnection()` by nothing outside the
     class. The integration tests' `getRawConnection()` is their own base
     class's.
   - `StatusService`: `getMigrationStatus()` and `hasChecksumColumn()` are
     called only by their tests; `TableNameService` serves only the second.
4. **Where `dbVersion` is shown or documented:** `SettingsController::getStatus()`,
   `ChecksumApi::getStatus()` (both through `StatusService::getDbVersion()`),
   the panel's row, `docs/api-v1.md` (two examples), `docs/api-v1-openapi.yaml`.
   `ShowStatus` shows none; [FAQ.md:628](../../docs/FAQ.md) says it does.

## Implementation Plan

### Block 1: Dead code out

1. **`StatusService`:** `getMigrationStatus()`, `hasChecksumColumn()`, and
   the `TableNameService` dependency they alone used.
2. **`DatabaseService`:** `columnExists()`, `getInstalledMigrations()`,
   `countRows()`, `tableExist()`, `getSchemaManager()`, and the `safe*()`
   helpers left without a caller; the class docblock rewritten for what
   remains. `getRawConnection()` stays until Block 2: the version still
   reads through it.
3. **Tests:** the removed methods' tests out; every `new StatusService(…)`
   without the `TableNameService` argument.

**Verification:** phpunit `unit` and `integration` on harness instance 34;
Psalm, ECS; `grep` finds none of the removed names in `lib/` or `tests/`.

### Block 2: The database by name and version

1. **`DatabaseService::getDatabaseVersion()`** returns `<Name> <version>`:
   - the name from `getDatabaseProvider(true)`: MariaDB, MySQL, PostgreSQL,
     SQLite, Oracle;
   - the version from `SELECT sqlite_version()` on SQLite and
     `SELECT VERSION()` otherwise, through `IDBConnection::executeQuery()`,
     its first `\d+(\.\d+)+`;
   - the name alone, plus "unknown", where the query fails or holds no
     number; the failure logged as now;
   - `getRawConnection()` then has no caller, and goes.
2. **`ShowStatus`:** "Database version:" after "App version:", and
   `database_version` in the JSON.
3. **Docs:**
   - `docs/api-v1.md`: both `dbVersion` examples → `MariaDB 10.11.6`, and
     what the value is;
   - `docs/api-v1-openapi.yaml`: `dbVersion`'s description and example;
   - `docs/FAQ.md`: the status answer, now true.

   `docs/api-v1*` and `CHANGELOG.md` are shared with worker 2's AP
   ListHashes: the other session is told before they are written, and one
   session's commit lands before the other edits the same file.
4. **Tests:**
   - `DatabaseServiceTest`: each provider with its query and its raw answer
     → the cleaned string; a failing query → name and "unknown"; SQLite
     never asked `VERSION()`;
   - `ShowStatusTest`: the line and the JSON key;
   - `CommandTest` (integration): `database_version` starts with the
     instance's backend name.

**Verification:** phpunit `unit` and `integration` on harness instance 34
(MariaDB); `occ fcias:status` there; the panel's row in the browser; Psalm,
ECS. SQLite and PostgreSQL by the unit tests only: no harness instance runs
them.
