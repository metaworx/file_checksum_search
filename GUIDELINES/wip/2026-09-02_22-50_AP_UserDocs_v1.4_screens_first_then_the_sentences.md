# AP UserDocs v1.4: screens first, then the sentences

> **Status: approved 2026-09-02.** Supersedes v1.3 by closing its two open
> decisions; everything else — analysis, blocks, verification — is v1.3's and is
> not repeated here. Read v1.3 for the plan; read this for the two answers and
> the one control they add.

## Decisions closed

1. **Default allowlist:** the eight compiled-in today plus `sha384` and
   `sha3-384`. Anything else PHP offers is an admin click away.
2. **Preference default:** a **global default for everyone**, the catalogue's
   default algorithm. On the personal settings page the preference select
   carries a first entry **"Default (<default>)"**, and beside the select the
   page states which algorithm is currently active for this user — the
   preference if one is set, otherwise the default. So a user who never opens
   settings gets the instance's default as their first quick button, and one
   who opens it can see why.

## What this changes in v1.3's plan

- Block 3, step 8: the personal control gains the *Default (<default>)* entry
  and the "active: <algo>" line; the `personal-options` payload therefore
  carries `preferred` (may be empty), `default`, and `active`.
- Sidebar composition, first line becomes
  `first := preferred ?? default` — the rule's first algorithm no longer
  stands in, because the default does.
