# AP MimeTypes v1.0: MIME types from the content

## Discussion

- **Origin.** The user's request of 2026-10-09: detect a file's MIME type
  from its content while hashing it, store it beside the hashes, and show
  it where the hashes are shown. Settled with the user on 2026-10-09 and
  2026-10-10; the decisions below are theirs.
- **Global, not per rule.** On a file being hashed, detection costs one
  libmagic call on a buffer already read. A rule flag would reach the rule
  model, validator, form, overrides and API, and save nothing. Nothing
  here prevents one later.
- **Off by default**, a switch under Advanced.
- **The API asks for it** with `?mimetype=1`. Off or unavailable: HTTP 400
  with a hint naming where to switch it on. On, with no type for the file
  yet: `null`, never `""`.
- **Delete only while off.** While on, the button is disabled with a hint:
  switch off to delete, or Refresh to bring them up to date. Switching on
  is refused while a deletion runs.
- **No delete mark.** Nothing shows the types while off, so they need no
  hiding first: the delete job walks the type's own rows. A renamed key
  (`file-checksum-mime-del`) and an int of -1 were weighed and dropped:
  each moves the row in all four indexes of the table, as deleting it
  does, and the second needs a filter in every reader.
- **The sidebar shows Nextcloud's own type beside it** where the two
  differ, without a warning: libmagic and core disagree on harmless pairs
  (`.md`: `text/plain` against `text/markdown`), so a warning would be
  noise.
- **`hashes?since=` does not see a refreshed type.** A refresh adds a type
  without writing the stamp, which vouches for hashes it did not compute.
  Documented: after a refresh, read again without `since`.
- **Backup and import leave the type out.** It is detected again from the
  content, and its id is the instance's own.

## Analysis

**PHP:** `finfo` is the Fileinfo extension: bundled with PHP and on by
default, but an extension, which a build can leave out. Nextcloud 33 to 35
list `fileinfo` among the required modules
(`PhpModules::REQUIRED_MODULES`). `IMimeTypeDetector::detectString()` runs
it on a buffer and returns libmagic's own answer, without core's
secure-type mapping. Without `finfo` the feature reports itself
unavailable, cannot be switched on, and detects nothing where it was on.

**Nextcloud's own type is the name's.** Every storage (local, object
store, WebDAV, SMB, SFTP, FTP, S3, Swift), chunked upload, the trash and
versions fill `filecache.mimetype` with `detectPath()`: the extension
through `mimetypemapping.json`, `application/octet-stream` for none or an
unknown one. A rename that changes the extension sets it again from the
new name (`Cache\Updater`). Content is read only by Flow's MIME check, for
a local file the cache calls `application/octet-stream`, and held for that
request.

**Storage:**
- **Key** `file-checksum-mimetype`: under the app's prefix, not the
  hashes' (`file-checksum-hash-`), so nothing counts or lists it as a
  hash. 22 characters; `meta_key` is varchar(31).
- **Document:** the full type. Registered unindexed, as the hashes are, so
  Nextcloud never rewrites its index row.
- **Index row:** `meta_value_int` the type's id, `meta_value_string` the
  type cut to 63. The Office types run to 73 characters
  (`…presentationml.presentation`), so the id is the exact value; the
  string serves prefix filters (`image/%`) and a reader. Both are covered
  by `fcias_f_metadata_int_idx` and `fcias_f_metadata_str_idx`; no
  migration.
- **Ids:** core's `oc_mimetypes`, through `IMimeTypeLoader::getId()` and
  `getMimetypeById()` (public since 8.2): an atomic insert under a unique
  index, cached per process. App config would race two workers adding one
  new type, and is rewritten whole. The ids are those `filecache.mimetype`
  uses. A type core never assigns gets a row there; nothing prunes that
  table.
- **Readers** take the row's id through `getMimetypeById()`: the full
  value, with no document read.

**Lifecycle.** The type describes the content, so it follows the hashes'
rule: its row exists only while it is current. Detection takes the first
64 KiB of the read that hashes the file.

| When hashes are computed                                  | The type in the document          |
|-----------------------------------------------------------|-----------------------------------|
| on, the file is read                                      | detected again                    |
| on, nothing read, a current document without a type       | the first 64 KiB read for it      |
| on, nothing read, the type there                          | left                              |
| off, its row there                                        | kept: the content did not change  |
| off, no row                                               | removed                           |
| off, `force`                                              | removed: it cannot be recomputed  |

Every other path follows the hashes: outdated, pruned, eroded, reset,
purged, rebuilt from documents. A rebuild writes no type row while the
feature is off. Hashes that arrive without a read (the filecache copy, an
import, the `checksum` column) leave a current document's type alone and
remove a non-current one's; Refresh fills in what is missing.

**Concurrency:** a read for the type alone follows `recalcHashes()`: the
app's lock, the etag before and after, the document still current.
Nextcloud's metadata save fails on a changed sync token rather than
overwriting.

**Bulk work:**
- **Refresh** (on only), *Missing* or *All*: a queued job marks hashed
  files `pending:mime`, a queue mode that reads 64 KiB and writes no
  stamp. *Missing* skips files with a type row. A file with any mark is
  skipped, and any hash mode later replaces this one. The drain's lock,
  failure count, skip of unavailable storage, `fcias:queue:drain` and the
  *Queued files* line apply as they are. While off, the drain drops the
  mark unread.
- **Delete** (off only): sets a *deleting* state and queues a job that
  walks the type's rows by file id, removing the key from the document,
  then the row. Each file is complete or gone at every moment, and the job
  goes on where it stopped. Switching on is refused while the state is
  set; the job clears it with the last row.

**Constraints:**
- SQL through `IQueryBuilder` only;
- every new text translatable, in every language kept here;
- with the feature off and no type stored, the hashes behave as they do
  now.

## Implementation Plan

### Block 1: detection and storage

1. `ConfigLexicon`: `mimetype_detection` and `mimetype_deleting`, both
   bool, off.
2. `MetadataService`: the key, registered unindexed, and
   `hashKeysAreUnindexed()` checking it too; the type written into a
   document, and its row from it (the id through `IMimeTypeLoader`, the
   string through `truncateForIndex()`); types read by file id; the
   lifecycle table on every path that prunes, erodes, resets, purges or
   rebuilds hashes; a count of type rows.
3. `HashCalculationService`: the first 64 KiB kept from the read in
   `computeMultiHash()` and the stream path of `computeSingleHash()`, and
   read apart beside the local `hash_file()`; detection through
   `IMimeTypeDetector::detectString()` where the feature is on and
   available; `keepOnly()` and `force` as the table says; the 64 KiB read
   for a current document without a type.
4. Tests:
   - unit: the head across chunk boundaries and of a file under 64 KiB;
     each row of the table; the row's id and cut string; the key
     unindexed;
   - integration: a PDF named `.jpg` gets `application/pdf`; an Office
     document keeps its full type in the document and the id, its string
     cut to 63; a changed file loses its type row; a rebuild while off
     writes none.

**Verification:** PHPUnit unit and integration on NC 33 and 34, ECS,
Psalm.
**CHANGELOG:** Added: MIME types detected from a file's content while it
is hashed, off by default.

### Block 2: refresh, delete, occ and status

1. `pending:mime` in `processFile()`: off, no include rule, or the
   document not current, and the mark is dropped; otherwise the 64 KiB
   read, the type written, the stamp untouched; a failed read counted as
   for the hash modes.
2. A queued refresh job (*Missing*, *All*) marking files by file id in
   pages; a queued delete job, queueing itself again until no type row is
   left, then clearing the *deleting* state. Both recorded by
   `JobStatsService` as jobs of their own.
3. `occ fcias:mimetype:enable`, `:disable`, `:refresh [--all]` and
   `:delete`, under the buttons' rules; `refresh` and `delete` do the work
   in the command, with a count, rather than queue it.
4. The status (`fcias:status`, the admin panel's counts, `/api/v1/status`
   for administrators): unavailable, disabled, disabled with N kept, N
   detected, deleting with N left.
5. Tests: unit for the mode, the jobs and the commands; integration for a
   refresh, a delete interrupted and resumed, switching on refused while
   deleting, and the counts.

**Verification:** as Block 1.
**CHANGELOG:** amends Block 1's bullet: refresh, delete and the status.

### Block 3: the API

1. `?mimetype=1` on `file/{id}/hashes`, `hashes`, `lookup`, `duplicates`,
   `file/{id}/duplicates` (one per group), `file/{id}/recalc` and
   `file/many/recalc`, each with its `sudo/` twin; HTTP 400 with the hint
   while off or unavailable, the hint in the 11 `.po` files; `null` for a
   file with none.
2. `/api/v1/status`: `features.mimetype` for every caller.
3. `ChecksumApi`: the same, as a parameter of each method behind those
   routes.
4. `docs/api-v1.md` and `docs/api-v1-openapi.yaml`.
5. Tests: controller unit tests per route, and HTTP integration tests for
   on, off and none.

**Verification:** as Block 1, and `scripts/l10n.sh check`.
**CHANGELOG:** amends Block 1's bullet: `?mimetype=1`, with the API
reference.

### Block 4: the interface

1. Admin → Advanced, a section *MIME types*: the switch, unavailable with
   its reason where `finfo` is missing; Refresh, with a dialog asking
   *Missing* or *All*; Delete with a confirmation, disabled while on, with
   the hint; the status line.
2. The sidebar: a *MIME type* row under the hashes, and the node's own
   `mime` beside it where the two differ.
3. The duplicates page: the type on each group's header, beside the
   algorithm.
4. The pages read `features.mimetype` once and send `?mimetype=1` only
   while it is on.
5. Every new text in the 11 `.po` files, and the glossaries' rows.
6. Tests: Vitest for the section, the sidebar row and the group header;
   Cypress for a file whose name and content disagree, and for the
   switch, Refresh and Delete.
