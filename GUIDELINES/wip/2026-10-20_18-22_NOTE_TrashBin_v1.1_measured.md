# NOTE TrashBin v1.1: measured

Block 1, 2026-10-20, on the harness's instances 33 and 34:
a test account's file hashed (sha1), overwritten once so that its version
holds the checksums handed on, then moved to the trash, restored,
moved to the trash again and deleted from it;
the rows, ETags, the app's metadata and the events at each step.
A home on 33 and 34, a team folder on 34 (33 has no groupfolders).

## What was measured

| Step | Home (33, 34) | Team folder (34) |
|------|---------------|------------------|
| **Moved to the trash** | the file id and ETag kept; the row at `files_trashbin/files/<name>.d<time>`; the app's metadata cleared, its index rows gone | the same, at `trash/<name>.d<time>` in the folder's storage |
| **Its version** | the id, ETag and checksums kept, at `files_trashbin/versions/<name>.v<mtime>.d<time>`, still current | stays at `versions/<file id>/<mtime>`, checksums kept |
| **Events** | `BeforeNodeDeletedEvent`, `MoveToTrashEvent`, `NodeDeletedEvent` | the same |
| **Restored** | the file id and ETag as before the trash; back at its path; no checksums, as cleared; the version back with its checksums | the same |
| **Restore events** | `BeforeNodeRestoredEvent`, `NodeTouchedEvent`, `NodeRestoredEvent`; no create or write | none of those, nor any node event |
| **Deleted from the trash** | `CacheEntryRemovedEvent` for the file and the version; their rows gone. 33: the version's metadata gone. 34: the version's checksums and index row stayed | the file's row gone; the version's row stayed, with its checksums |

The trash's own record holds the path before the deletion
(`ITrashItem::getOriginalLocation()`):
`T/a.txt` for the home, `<folder>/a.txt` for the team folder;
the filecache path keeps the name alone.

## What it changes in the design

- **Keep and restore (Block 2)** is smaller than designed:
  a file that keeps its checksums in the trash comes back with them proved,
  since both restores keep its id and its ETag.
  No restore needs hearing, and a team folder's fires nothing to hear.
  `FileListener::onDelete()` stops clearing a file moved into the trash;
  a restored file without checksums is the sweep's, as one written while no rule
  covered it is.
- **Results (Block 3)** take a file's path before the deletion from the trash's
  own tables (`files_trash`, `group_folders_trash`), not from the filecache.
- **Versions in the trash (Block 4):**
  a home's are by name in `files_trashbin/versions/`,
  a team folder's stay by file id beside the folder's other versions.
- **What deletion leaves:**
  on 34, the metadata of a home version deleted from the trash,
  which the orphan purge collects, its row being gone;
  in a team folder, the version's row of a deleted trash item,
  which groupfolders leaves, and which is in no answer, its file being gone.
