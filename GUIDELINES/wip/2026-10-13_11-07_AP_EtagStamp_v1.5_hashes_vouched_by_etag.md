# AP EtagStamp v1.5: Hashes vouched by ETag

## TL;DR

Blocks 1–12 are in. Block 13 is now stricter: a restore uses the ETag to
tell whether the file changed since the backup, which the mtime cannot see
after a sync client uploads with an old mtime. The ETag lives in the
stamp row alone; `oc_filecache.etag`, which clients compare, is never
written.

- Export → each hash record carries its stamp's ETag: a JSON key, a CSV
  column; `sum` none
- Import, `--stamp=source`, ETag equal to the file's → stamped with it,
  vouched by it
- ETag different, JSON backup of this instance → changed since the backup:
  refused and counted; `--allow-stale` stores it with its ETag, out of
  search until hashed
- ETag different from another instance or a CSV, or none → as today
- `--stamp=mtime|now` → the admin's word, as today

## Discussion

v1.4's decisions stand. Its Block 13 stamped the ETag only where it
matched and otherwise imported as before. That gained a day at most,
since the daily walk adopts the present ETag for a stamp the mtime rule
holds, and it missed the gap that matters: a file changed between backup
and restore with its mtime kept. Decided at the gate:

- **Clients never resync over this.** The import writes the ETag into the
  app's stamp row only, and only the one the file has or, refused, had.
- **No new power for the importer.** Import is `occ` only; a matching ETag
  vouches as `--stamp=now` already lets that admin vouch; ETags are public
  through WebDAV's `getetag`.
- **"Different" means "changed" on this instance only.** ETags are random
  per change and per instance, so a different one from elsewhere says
  nothing. The JSON header's `instance_id` names the instance; a CSV
  names none, so a CSV uses equality alone.
- **One edge refuses wrongly:** an instance rebuilt on a fresh database
  under its old `instanceid` has new ETags for every file. The report
  counts the files and names `--stamp=mtime` to take them on the mtime's
  word.
- **Additive formats.** CSV is read by header and JSON by key, so an older
  version ignores the field and a backup without it imports as today; the
  JSON schema version stays.

## Analysis

Checked against HEAD:

- `HashRecord` carries storage, path, algorithm, hash and `updatedAt`;
  `FormatOptions::anchor()` rebuilds a record field by field, so a new
  field has to be passed through there.
- `CsvFormat::COLUMNS` writes five columns; `read()` maps by the header.
  `JsonFormat` writes `toArray()` and reads `fromArray()`.
- `MetadataService::exportHashes()` yields `updated_at` from the document;
  the stamp's ETag is the document's `file-checksum-etag`.
- `ImportService::applyFile()` decides one stamp per file from its first
  record (`stampFor()`); `writeHashes()` then stamps it with no ETag.
- `FilecacheService::locateAllByPath()` selects `fileid`, `path` and
  `mtime`; `FileLocation` has no ETag.
- `ImportService::checkHeader()` reads the header and logs its
  `instance_id`; nothing compares it.
- `ImportReport` counts `skippedOutdated` among others; `fcias:import`
  prints them.

## Implementation Plan

### Blocks 1–12

Done, as v1.1 and v1.4 describe them.

### Block 13: A restore judges by the ETag

1. `HashRecord` gains `?string $etag` (in `fromArray()`, `toArray()` and
   `anchor()`); `CsvFormat` a column `etag`; `JsonFormat` a key; `sum`
   none.
2. `exportHashes()` yields the stamp's ETag; `ExportService` puts it on
   the record.
3. `FileLocation` gains `etag`; `locateAllByPath()` selects it.
4. `ImportService`: the header's `instance_id` against this instance's
   decides "this instance"; under `--stamp=source`, as the TL;DR's
   bullets say.
   A refusal for a changed file is counted as `ImportReport::$changed`,
   apart from `skippedOutdated`. `writeHashes()` takes the ETag to stamp.
5. `fcias:import` prints the new count, with the hint `--stamp=mtime`;
   its help and `fcias:backup`'s name the column.
6. README, *The timestamp is the dangerous part of an import*: the ETag
   rule; *Only `json` is a backup*: CSV's columns.
7. CHANGELOG, Added (draft):
   `` - `occ fcias:backup`, `fcias:import`: a hash carries its ETag, and a``
   `  restore refuses one the file has changed since, on this instance.`

Writing `CHANGELOG.md` waits until the session working on AP DbVersion
says it is free, as that session asked.

**Verification:** unit: the record round trip through CSV and JSON, an
old CSV without the column, `anchor()`; `ImportService` for each of the
TL;DR's cases. Integration: back up, revoke with `--now`, import: the
stamp row carries the ETag and the lookup finds the hashes; the file changed in
between: refused and counted, and with `--allow-stale` stored and not
found; a CSV with a foreign ETag imports as today. Both suites on 33 and
34, ECS, Psalm, `changelog.sh check`.
