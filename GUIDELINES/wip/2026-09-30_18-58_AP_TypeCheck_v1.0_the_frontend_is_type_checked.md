# AP TypeCheck v1.0: the frontend is type-checked

## Discussion

- The user, 2026-09-30: "write the tsc plan with optional CI", after
  `npx tsc -p tsconfig.json --noEmit` reported 44 errors that nothing in the
  project had ever shown.

## Analysis

**Nothing checks the frontend's types today:**
- there is no `typecheck` script and no `vue-tsc`;
- the build (Vite) strips types without checking them;
- ESLint does not check types;
- CI's Lint job (`.github/workflows/test.yml`) runs ESLint, Stylelint, the
  PHP syntax check, the manifest and the translations.

**Plain `tsc` finds 44 errors, in four groups:**

| Count | Error | Cause |
|---|---|---|
| 23 | TS2307, "Cannot find module './X.vue'" | Plain `tsc` cannot read `.vue` files. There is no `declare module '*.vue'` shim, only `src/types/svg.d.ts`. |
| 17 | TS2339, "Property … does not exist" | All in `src/duplicates-vue/composables/useDuplicates.spec.ts`. The test groups are untyped object literals, inferred as `{fileid, path, name}`, and the spec reads the fields the composable adds (`verified`, `verify_error`, `match_count`, `mismatch_count`). |
| 3 | TS2353, "Object literal may only specify known properties" | Stale test data: `pinned` in `src/rules-vue/RuleTable.spec.ts:91`, and `userScope` in `src/rules-vue/composables/useRules.spec.ts:68` and `:73`. The code dropped both in earlier refactors, and the specs pass because the extra properties are ignored. |
| 1 | TS2322 at `useDuplicates.spec.ts:38` | The fetch mock's type annotation does not match what `vi.spyOn(globalThis, 'fetch')` returns. |

**`vue-tsc`** checks `.vue` files as well as `.ts`, and makes the shim
unnecessary. It will also check the `<script setup>` blocks, which nothing
has checked so far, so it may report errors plain `tsc` cannot see. Their
number is unknown until it runs.

**Versions:** TypeScript 5.9.3, Vue 3.5, `@vue/tsconfig` 0.9.1. `vue-tsc`
3.x supports that combination.

## Implementation Plan

### Block 1: the check, and a tree that passes it

1. **The check itself:**
   - `vue-tsc` as a devDependency;
   - `"typecheck": "vue-tsc --noEmit -p tsconfig.json"` in `package.json`.
2. **Run it, and fix what it reports:**
   - the 17 property errors: the test groups typed with the composable's
     own `DuplicateGroup` and `DuplicateFileItem` types;
   - the 3 stale properties removed;
   - the fetch mock's annotation corrected;
   - whatever `vue-tsc` reports in `.vue` files.

   **If it reports more than about 20 errors in `.vue` files, or any that
   would change runtime behaviour, stop and gate** with the list before
   fixing them.
3. **The contract** (`GUIDELINES/project/_CONTRACT.md` §1): the lint row
   names `npm run typecheck`. The contract goes to v2.11.0 with its
   history row, and `AGENTS.md` and `GUIDELINES/README.md` are regenerated.
4. **CHANGELOG, Changed:** the frontend is type-checked, `npm run typecheck`.

**Verification:**
- `npm run typecheck` reports 0 errors;
- Vitest, ESLint and the build pass;
- the specs still assert what they did: no expectation is changed or
  loosened to satisfy a type.

### Block 2 (optional): CI runs it

1. **`.github/workflows/test.yml`:** the Lint job gains
   "Type check: `npm run typecheck`", after ESLint.
2. **CHANGELOG:** none, `.github/` is not a shipped path. The message says
   so.

**Verification:** the workflow file parses (`yamllint` or a YAML load); the
step runs on the next push.
