# AP Vocabulary v1.1: the frontend's names catch up with the model

> **Status: approved 2026-09-02.** Independent of every other open AP.
> Renames DOM ids and CSS classes and the tests addressing them. No stored data,
> no API, no behaviour.

## Discussion

Three words in the frontend name a model this app no longer has.

- **`cron`** — `#fcias-cron-list`, `#fcias-cron-form`, `.fcias-cron-table` and a
  dozen more. Nothing on the rules page is a cron job; the rule sweep and the
  queue drain are, and they have no markup here. Left over from when hashing was
  configured as a schedule.
- **`userscope` / `scope-target`** — `#fcias-cron-userscope` is the **selector**
  field. `RuleForm.vue` already calls its own state `selectorChoice` and
  `selectorTargetValue`: a rename applied to the script and never carried to the
  template.
- **`definition`** — `#fcias-btn-add-definition`, `-save-`, `-cancel-`. A rule
  was a definition before it was a rule.

**Counted:** `cron` 117 in `src/`, 40 in `tests/e2e/`. `userscope`/`scopeTarget`
~42 in `src/`. The `-definition` buttons, 15.

## Analysis

### What must NOT be renamed

The same words appear elsewhere meaning something true. A repository-wide `sed`
breaks four of these; one has a test that would notice.

| Occurrence | Why it stays |
|---|---|
| `cron` in `lib/Command/Queue/Drain.php` (2), `lib/Service/RuleOverrides.php`, `lib/Migration/RepairQuietStart.php` | Means actual cron — "when cron is not running". |
| `cron` in `docs/FAQ.md` (2) | "How does cron / pending processing work?" — the scheduler. |
| `$rule['userScope']` in `lib/Service/RuleService.php` (5), plus a `RepairQuietStart` comment (1) | **The stored legacy key.** `ruleSelector()` falls back to it so pre-selector rules still resolve. Renaming breaks every upgrade from an older version, silently. `RepairQuietStartIntegrationTest` covers it. |
| `$userScope` in `lib/Command/HashFiles.php` (6) | A local for the `--user` option. About users, not selectors. |
| `rule_definitions` (`ConfigLexicon`, `RuleService::CONFIG_KEY_RULES`, `JsonFormat`'s backup shape) | **Persisted, and in the backup format.** A backup written before the rename must restore after it. |

### Out of scope

`RuleDefinitionValidator`, `definitionValidator`, the `RuleDefinition` type
(backend). "Definition" for a rule's *shape* is defensible, none of it is
addressable from a test, and renaming backend types is a separate decision.

### Risk

Every e2e selector changes at once, so the suite either matches or dies in
`before()` — no silent partial failure, but it can only be verified by running,
and must not be interleaved with other edits to the same files.

### Naming

Prefix split: `fcias-rules-` for the collection, `fcias-rule-` for one rule.

| Now | After |
|---|---|
| `fcias-cron-list` | `fcias-rules-list` |
| `fcias-cron-table` | `fcias-rules-table` |
| `fcias-cron-actions` | `fcias-rules-actions` |
| `fcias-cron-msg` | `fcias-rules-msg` |
| `fcias-cron-form`, `-form-row`, `-form-static`, `-form-actions`, `-form-fill` | `fcias-rule-form…` |
| `fcias-cron-path`, `-type`, `-mode`, `-algos`, `-admin-enforced` | `fcias-rule-path`, … |
| `fcias-cron-snippet`, `-snippet-container` | `fcias-rule-snippet…` |
| `fcias-cron-userscope` | `fcias-rule-selector` |
| `fcias-cron-scope-target` | `fcias-rule-selector-target` |
| `fcias-btn-add-definition` | `fcias-btn-add-rule` |
| `fcias-btn-save-definition` | `fcias-btn-save-rule` |
| `fcias-btn-cancel-definition` | `fcias-btn-cancel-rule` |

`#fcias-btn-refresh-status`, `#fcias-personal-*`, `#fcias-status-*`,
`#fcias-idle-banner` and the `data-*` hooks are already right; untouched.

## Implementation Plan

### Block 1 — `cron` and `definition` · `[TASK]`

1. Rename the identifiers in `src/` (`RuleForm.vue`, `RuleTable.vue`,
   `RuleRow.vue`, both settings `App.vue`, any SCSS) and `tests/e2e/*.cy.js`.

**Verification:** whole e2e suite green twice. `grep -ri cron src/ tests/` empty;
`grep -rn cron lib/ docs/` returns exactly the six legitimate occurrences.

### Block 2 — `userscope` → `selector` · `[TASK]`

4. `#fcias-cron-userscope` → `#fcias-rule-selector`, `#fcias-cron-scope-target`
   → `#fcias-rule-selector-target`, and the `ids` map in `RuleForm.vue`. The
   script-side `selectorChoice` / `selectorTargetValue` are already correct.
5. Same commands, same verification.

**Verification:** as Block 1, plus `grep -ri userscope src/ tests/` empty and
`grep -ron userScope lib/ | wc -l` returning exactly **12** — five in
`RuleService`, six in `HashFiles`, one in a `RepairQuietStart` comment.

### Block 3 — the words in prose · `[TASK]`

6. Sweep `src/` comments, `tests/e2e/README.md` and the user-facing docs for
   sentences calling the rules page a cron page or a rule a definition.

**Verification:** read the diff. No test covers this.

## Proposed commit message

(First commit of the series.)

```
[TASK] Stop calling the rules page a cron page

Nothing here is a cron job. The two things that are scheduled — the rule
sweep and the queue drain — are background jobs with no markup on this
page at all. The word is left over from when hashing was configured as a
schedule rather than as rules.

The buttons lose "definition" with it: a rule was a definition before it
was a rule.

Renames ids and classes only. The four occurrences of `cron` in lib/ and
the two in docs/ mean actual cron and stay; so does the stored
`rule_definitions` config key, which a backup written before this must
still restore after it.
```

No CHANGELOG bullet: nothing a user or an API client can observe.
