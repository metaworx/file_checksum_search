# AP UserDocs v1.0: True up user-facing documentation

> **Status: preliminary — not yet approved.** Analysis-only session; nothing has been edited.
> Blocks 1 and 7 touch shipped code (`appinfo/info.xml`, `src/`) and need CHANGELOG bullets;
> AP Screenshots should capture only after Block 7's UI strings land. Independent of AP E2ETests.

## Discussion

- The markdown docs were rewritten in commit 6a476b7 and are **structurally sound** — the README's
  model chapters, CLI reference (verified against `appinfo/info.xml:67-80`: 12 commands, grouping
  and flags correct), rate limits, reorder body, the 403-excluded payload and the band story all
  check out against code. What is wrong is concentrated in the **API documentation's addressing
  and status codes**, one **dead shipped link**, and a handful of **in-UI help strings** still
  speaking the pre-selector model.
- Two findings break real clients today: every URL in `docs/api-v1.md` and the OpenAPI `servers`
  entry lacks the `/ocs/v2.php` prefix (probed live: `/index.php/apps/...` and `/apps/...` return
  404; only `/ocs/v2.php/apps/file_checksum_search/...` answers, with a **plain JSON** body since
  the controllers extend `ApiController`, not `OCSController` — `docs/api-v1.md:280`'s "no OCS
  wrapper" is right, its prefix is wrong); and `min_count` is documented where the controller
  binds `minCount` (`lib/Controller/PublicApiController.php:188`), so the documented parameter is
  silently ignored.
- One decision this AP takes and states rather than hides: the `/settings/*`, `/duplicates/data`,
  `/admin/docs` and `/help` endpoints stay **out of the OpenAPI spec deliberately** — they are
  UI-internal, admin-gated surfaces the app's own pages consume, not public API. The docs gain a
  sentence saying exactly that, because an undocumented endpoint someone finds in the network tab
  reads as an oversight unless the scoping is written down. (`GET /duplicates/data`'s admin-only
  `user` param — 403 `'Only admins can query other users.'`, 404 `'User not found.'`,
  lib/Controller/DuplicatesController.php:299-312 — is mentioned in that internal-endpoints note,
  since it is a real capability.)

### B. `docs/api-v1.md` — wrong claims (verified against controllers; each with the fix)

2. **Base URL** at :7, :280, :306, :340, :363, :390, :434, :469 and the curl examples :680, :691 —
   all say `/apps/file_checksum_search/api/v1/...`; every one 404s. Change to
   `/ocs/v2.php/apps/file_checksum_search/api/v1/...`; keep the "plain JSON, no OCS wrapper"
   sentence and add: with cookie sessions send `OCS-APIRequest: true` (that header, not
   `#[NoCSRFRequired]`, is what carries the rule mutations past CSRF —
   nextcloud-v34/lib/private/AppFramework/Http/Request.php:455-457); with basic auth it is
   optional (probed).
3. **`min_count` → `minCount`** at :434, :440 (controller binds by exact name; the frontend sends
   `minCount`, src/duplicates-vue/composables/useDuplicates.ts:77).
4. **PHP signatures omit the security-relevant `?string $requestingUser = null`**:
   `findByHash` (:70 vs lib/Public/ChecksumApi.php:195-200), `getHashesByFileId` (:94 vs :86-89 —
   that param is what produces NotFoundException on a foreign fileId), `recalcHash` (:218 vs
   :380-384). Document the parameter and its trusted-caller semantics (null = server-side
   authority), which the changelog already promises.
5. **`findDuplicates` is per-user, not "across the entire system"** (:160-162): code resolves the
   session user, `listDuplicatesForUser` (lib/Public/ChecksumApi.php:248-264), and a session-less
   caller gets an empty set. Rewrite; the matching code docblock fix is AP CodeDocs Cat-1 #14.
6. **":696 All API endpoints use `#[NoCSRFRequired]`" is false** for the four rules mutations and
   two settings POSTs — replace with the OCS-APIRequest explanation from item 2.
7. **":700 Rule management is not exposed through the public API"** contradicts the same file's
   endpoints 7-12 and `ChecksumApi`'s rules methods. Delete the sentence.
8. **Error text** ":234 `'File not found: 99999'`" → actual `'File not found.'`
   (lib/Service/HashCalculationService.php:869).
9. **Status table :804-810** omits 401 (returned by getHashes/lookup/recalc/apply) and 403;
   ":822-828 all errors are `{error}`"** is false for rules and recalc (`{success:false, error}`) —
   state both shapes. Also note the asymmetry: an admin asking `/file/{fileId}/hashes` for an
   unknown id gets 200 with empty `hashes`, the 404 fires only for non-admin scope
   (lib/Public/ChecksumApi.php:91-94).
10. **Broken relative links** :11 and :29 → `lib/Public/ChecksumApi.php` resolves against `docs/`;
    prefix `../`.

### C. `docs/api-v1-openapi.yaml` — spec errors

11. `servers.url` :17 → append `/ocs/v2.php` before `/apps/...` (with item 2's header note as a
    spec description; the stale root stub is, ironically, the only file stating the prefix right).
12. **Status codes**: :67-68 lookup has no 404 (code: 200/400/401/500,
    PublicApiController.php:296-329); :121-122 file-duplicates has no 404 (empty 200 or 500);
    :164-165 recalc's not-found is **400**, only `excluded` maps to 403 (:389-394); :218-219
    all-duplicates has no 400 (limits are clamped, ChecksumApi.php:246). Add the missing **401**
    on getHashes/lookup/recalc/apply (:360-379 lists only 200/400/403/404).
13. **Shapes**: `HashEntry` :515-524 lacks `updated_at` (code emits it, ChecksumApi.php:105-110;
    api-v1.md:352 shows it); `SameHashResponse` :526-533 must not require `file_count`
    (ChecksumApi.php:345-350 builds only algo/hash_value/files); `RuleInput.required: [path]`
    :699 is not enforced (absent path defaults to `'/'`, RuleDefinitionValidator.php:68);
    `RuleMutationResponse.rule` :297/:411 promises a full `Rule` (id/band/position/…) but the
    controller echoes only the validator's definition (RulesController.php:214-217, :290-293) —
    **a POST caller never receives the new rule's id** (generated later inside `ruleAdd()`,
    RuleService.php:924-930). Document the minimal echo now; returning the full rule incl. id is
    a separate code ticket this AP raises at its gate, not a doc edit.
14. Cosmetic: tag casing `rules` vs `Rules` (:252 et al. vs :345), neither declared in `tags:`
    (:903-909); `hash` `minLength: 8` (:39) and the md's "8/32/40/64/128 chars" (api-v1.md:76)
    vs code's only-non-empty check (ChecksumApi.php:202-207) — either validate in code or soften
    the docs (docs-side softening proposed).
15. **Root `openapi.json`**: the untouched NC-skeleton stub — version `0.0.1` (:5), one invented
    `api-index` endpoint (:49-53), none of the 12 real ones. Excluded from the package
    (.nc.publish.ignore:53) but tracked and misleading. → `git rm` (regenerating a real spec is
    out of scope while docs/api-v1-openapi.yaml is the maintained one; say so in the commit).
