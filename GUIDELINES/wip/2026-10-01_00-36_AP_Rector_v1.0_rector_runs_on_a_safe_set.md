# AP Rector v1.0: Rector runs on a safe set

> **Status: proposal, 2026-10-01; for after 0.21.0.** `rector.php` came
> with the Nextcloud app skeleton and has never run. The contract's lint
> row stops naming `composer rector` in a commit ahead of this plan.

## Discussion

Decided with the user, 2026-10-01:

- **After the release.** Rector rewrites code across `lib/` and `tests/`,
  so running it before 0.21.0 would mean running the release tests again.
- **Out of the lint row until it runs.** The contract says what works,
  and `composer rector` does not.

Proposed here, open at the gate:

- **A rewriting tool, not a check.** It runs by hand and the diff is
  reviewed like any other. CI runs `rector --dry-run` only once the
  chosen set leaves nothing to change, so that it catches code that
  drifts from the set rather than proposing a rewrite on every push.
- **A small set first:** the PHP 8.2 language set and type declarations.
  The skeleton's dead-code, privatisation, `final` and coding-style sets
  stay out (Analysis 3).

## Analysis

1. **The config does not load.** Rector 2.6.7 stops on the
   `strictBooleans` prepared set, which Rector 2 removed:
   `Unknown named parameter $strictBooleans`. The script
   (`rector && composer cs:fix`) has never run.
2. **Without that set:** a dry run, from a scratch install over the
   checkout, would change 124 files, about 4,000 diff lines. The most
   frequent rules:

   | Count | Rule |
   |---|---|
   | 77 | `FinalizeTestCaseClassRector` |
   | 63 | `RemoveParentCallWithoutParentRector` |
   | 57 | `RemoveUnusedPrivateMethodRector` |
   | 57 | `PrivatizeFinalClassMethodRector` |
   | 45 | `ReadOnlyPropertyRector` |
   | 28 | `TypedPropertyFromCreateMockAssignRector` |
   | 26 | `CatchExceptionNameMatchingTypeRector` |
   | 23 | `PostIncDecToPreIncDecRector` |

   It also reported 13 system errors ("Class `OCP\AppFramework\App` not
   found").
3. **What would break:**
   - **`RemoveParentCallWithoutParentRector`** removes `parent::setUp()`
     from `DatabaseTestCase` and every integration test on it. Rector
     cannot load Nextcloud's `Test\TestCase`, or any class the
     `nextcloud/ocp` package declares without an autoloader, so it
     concludes the class has no parent.
   - **`RemoveUnusedPrivateMethodRector`** removes test helpers in about
     ten test classes, and would remove `RepairQuietStart`'s steps, which
     are reached through a method table. Psalm had the same blind spot
     (AP Psalm dropped its unused-code check for it).
   - **The style sets** (`final`, privatisation, `++$i`, quote escaping)
     conflict with, or duplicate, the house style ECS already enforces
     through `mwx/coding-standard`.
4. **Loading the server.** `tests/bootstrap.php` already finds a Nextcloud
   tree: the server the app sits in, or a source tree beside it
   (`nextcloud-v*`), or `FCIAS_NC_ROOT`. Its autoloaders
   (`3rdparty/autoload.php`, `lib/composer/autoload.php`) are what Rector
   needs through `withBootstrapFiles()`. In the harness container, the app
   sits inside a server, so there the classes are there.
5. **Installation** follows Psalm's pattern: `vendor-bin/rector`, the PHP
   platform 8.2.27.

## Implementation Plan

### Block 1: installation, configuration

1. `vendor-bin/rector/composer.json`: `rector/rector ^2.6`, then
   `composer bin rector install`, with its lock committed.
2. `rector.php`:
   - paths `lib/` and `tests/`;
   - `withBootstrapFiles()`: a small `tests/rector-bootstrap.php` that
     loads the server's autoloaders the way `tests/bootstrap.php` finds
     them, and never `lib/base.php`;
   - `withPhpSets(php82: true)`, and `withPreparedSets(typeDeclarations:
     true)` only;
   - `withSkip()` for `RepairQuietStart`'s steps, with the reason.
3. `composer.json`: `rector` stays `rector && composer cs:fix`, and
   `rector:check` (`rector --dry-run`) is added.

**Verification:** `composer rector:check` runs in the container with no
system errors, and reports what Block 2 applies.

### Block 2: the rewrite

1. `composer rector`, then review the diff rule by rule. A change that
   alters behaviour is reverted and the rule skipped, with the reason in
   `withSkip()`.
2. Unit and integration suites, ECS, Psalm; Cypress over the specs whose
   code changed.

**Verification:** `composer rector:check` reports nothing; unit and
integration on harness instance 34; `composer cs:check`; `composer psalm`.

### Block 3: CI and the contract

1. `.github/workflows/test.yml`, Lint job: install `vendor-bin/rector`,
   then `composer rector:check`. It needs the server's autoloaders, so it
   either joins the PHPUnit job, which has a server, or fetches a
   server's source.
2. `GUIDELINES/project/_CONTRACT.md`, lint row: `composer rector` (by
   hand) and `rector:check` (CI), and what the set is; regenerate.

**Verification:** the Lint job passes on the pushed branch;
`sync-docs.sh --check`.

Not in scope:
- The skipped sets (Analysis 3). Each is its own decision later, with its
  own diff.

CHANGELOG: Blocks 1 and 3 are tooling, exempt. Block 2 changes shipped code
without changing behaviour: `[CLEANUP]`, exempt under COMMIT.md §5.1
unless a rule turns out to change behaviour. Then that change is a
`[FIX]` of its own.
