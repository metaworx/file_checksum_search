# AP EmptyFiles v1.0: empty files hidden by default

> **Status: proposal, 2026-09-30.** On jackal (Nextcloud 33.0.5, app
> 0.20.2) the Duplicates page opens on a group of 605 files with SHA-1
> `da39a3ee…`: the SHA-1 of no input. All 1,477 index rows carrying it
> have `size = 0` in `oc_filecache`. Deleting an empty copy frees nothing.

## Discussion

Decided with the user, 2026-09-30:

- **A switch, not a size filter.** "Show empty files", off by default. No
  min or max size. A min size belongs with showing each group's size and
  sorting by wasted space, which all need `oc_filecache`; that is another
  plan. A max size has no use anyone named.
- **The OCS listing excludes empty files by default**, and
  `includeEmpty=1` brings them back. This changes what an existing caller
  gets back, so `docs/api-v1.md` and the changelog say so.
- **The PHP API follows the OCS route.** `findDuplicates()` and
  `findDuplicatesFor()` get the same parameter with the same default. One
  listing should have one default, and the route is a thin wrapper over
  them. *Not stated by the user; objectable at the gate.*
- **The sidebar collapses an empty group** into one line, "N other empty
  files", with a link that opens the Duplicates page on that group in a new
  tab.
- **The command line matches the page.** `find-duplicates` gets
  `--include-empty`.

## Analysis

1. **Groups are ordered by size, largest first.**
   `MetadataService::queryDuplicates()` orders by `cnt DESC`. An instance's
   empty files form the largest group, one group per algorithm, all on
   page 1.
2. **The index holds no size.** `files_metadata_index` has the file id, the
   key and the value. Filtering by size means joining `oc_filecache` inside
   a query that already groups the whole index. The Discussion rules that
   out.
3. **The empty digest is a constant per algorithm**, `hash($algo, '')`.
   Excluding it takes one predicate per algorithm on columns the query
   already reads:
   `i.meta_key <> :key OR i.meta_value_string <> :digest`. That is
   `IQueryBuilder` `orX`/`neq` only, so it works on every backend. The
   digest is truncated to 63 characters with `truncateForIndex()`, as every
   index value is.
4. **The key is part of each predicate**, not a `NOT IN` over the digests
   alone. On the NC34 harness, PHP offers 37 algorithms under key-legal
   names, with 29 distinct empty digests. Several of them are 8 hex
   characters: adler32 `00000001`; crc32, crc32b, crc32c, joaat and
   murmur3a `00000000`; fnv132 and fnv1a32 `811c9dc5`; xxh32 `02cc5d05`. A
   value-only filter would drop, say, a crc32 group whose value is
   `00000001`.
5. **What the predicate cannot tell apart.** A checksum as weak as a 32-bit
   one can map non-empty content to the empty digest. For example,
   65,521 zero bytes give adler32 `00000001`. Such a group is hidden along
   with the empty files it shares a value with. Those groups are already
   unreliable, which is what *Verify* is for. The alternative is the
   `oc_filecache` join of Analysis 2.
6. **Which algorithms.** Every name `hash_algos()` offers that matches
   `AlgorithmCatalogue::NAME_PATTERN`, not only the allowed ones. Rows
   written under a since-disallowed algorithm still form groups, because
   the listing matches keys with `LIKE`. With an algorithm filter, only
   that algorithm's pair is needed.
7. **Marking, as well as excluding.** When the page is asked to include
   empty files, it has to show which group is which. The sidebar has to
   know which group to collapse. So every group gets `empty` (bool),
   comparing the full value from the JSON document with its algorithm's
   digest. The listing (routes 5, 18) and the per-file lookup (routes 3,
   16) both carry it. Adding a response field is allowed in v1
   (`docs/api-v1.md`, "What Constitutes a Breaking Change?").
8. **The per-file lookup filters nothing.** `findSameHash()` answers for
   one file the caller named, and the sidebar decides how to show the
   answer.
9. **"Find across accounts" on an empty file.** `crossAccountUrl()` opens
   the Others tab filtered to the file's hash. With the new default, that
   tab would show nothing. The link sets `includeEmpty` when the sidebar's
   node has size 0. A file of size 0 has the empty digest under every
   algorithm, so this matches the server's rule.
10. **The documentation's examples use the empty SHA-1** (`docs/api-v1.md`
    routes 3 and 5) with non-empty file names. Under the new default,
    route 5's example would not be returned, so both examples change to
    another digest.
11. **The e2e fixtures carry content** (`tests/e2e/support/e2e.js`, PUT
    with a body), so no existing case depends on an empty group.

## Implementation Plan

### Block 1 — server

1. `lib/Service/AlgorithmCatalogue.php`: `public static function
   emptyDigests(): array<string, string>`. It maps each name of
   Analysis 6 to `hash($name, '')`. The docblock explains why it covers
   more than the allowlist.
2. `lib/Service/MetadataService.php`:
   - `private function andWhereNotEmpty(IQueryBuilder $qb, ?string $algo)`
     adds the predicates of Analysis 3 and 4: one pair, or none if the algo
     computes nothing PHP knows.
   - `queryDuplicates(…, bool $includeEmpty = false)` calls it unless
     `$includeEmpty`.
   - Each group row gains `empty`.
   - `public static function isEmptyDigest(string $algo, string $hash):
     bool` serves both the rows and `findSameHash()`.
3. `DuplicateService::findAllDuplicates()`,
   `HashIndexService::findAllDuplicates()` and `listDuplicatesForUser()`,
   `ChecksumApi::findDuplicates()` and `findDuplicatesFor()` each get
   `bool $includeEmpty = false` as their last parameter and pass it on.
4. `ChecksumApi::findSameHash()`: each group gains `empty`.
5. `lib/Controller/PublicApiController.php`: `findAllDuplicates()` and
   `sudoFindAllDuplicates()` take `bool $includeEmpty = false`, pass it by
   name, and log it.
6. `lib/Command/FindDuplicates.php`: `--include-empty` (VALUE_NONE).
   - Plain output marks an empty group, e.g. `(empty files)` after the
     hash.
   - JSON output carries `empty`.
7. Unit tests:
   - `MetadataServiceTest`: the pairs are built for all algorithms, one
     pair with an algo filter, none with `$includeEmpty`; `empty` is set on
     a row.
   - `AlgorithmCatalogue`'s test: `emptyDigests()` holds sha1 `da39a3ee…`
     and adler32 `00000001`, and no key-illegal name.
   - `DuplicateServiceTest`, `HashIndexServiceTest`: the parameter passes
     through.
   - `PublicApiControllerTest`: the default is `false`, and
     `includeEmpty=true` reaches the API.
   - `FindDuplicatesTest`: the option, and the plain and JSON marking.
8. `tests/Integration/Http/PublicApiTest.php`: two empty files and two
   files with identical content.
   - `/api/v1/duplicates` lists only the second pair.
   - With `includeEmpty=1`, it lists both, and only the first pair has
     `empty: true`.
   - `/api/v1/file/{id}/duplicates` on an empty file answers its group with
     `empty: true`.

**Verification:** `composer cs:check`, `composer psalm`; phpunit `unit`
and `integration` on harness instance 34.

## Proposed commit message

```text
[TASK] Empty files are left out of the duplicates listing by default

Empty files all share one checksum per algorithm, so on an instance with many of them their group topped the Duplicates page, and deleting a copy frees nothing.

Key changes:
- listing: empty files are excluded unless asked for, on the page (a "Show empty files" switch), the OCS route and PHP API (`includeEmpty`) and `find-duplicates` (`--include-empty`); every group carries `empty`
- Files sidebar: an empty file's duplicates collapse to a count, with a link to them on the Duplicates page
- docs: the parameter, the field, a compatibility-table row for narrowing a default, examples on a non-empty digest

An empty file is recognised by its algorithm's empty digest, one predicate per algorithm on columns the listing already reads, not by joining `oc_filecache` for its size. A 32-bit checksum can give non-empty content the same value, and such a group is hidden with the empty files; *Verify* is what tells those apart.

AP EmptyFiles v1.0.

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```
