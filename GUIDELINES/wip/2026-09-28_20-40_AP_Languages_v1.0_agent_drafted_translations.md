Held in the session scratchpad while another session works in the checkout;

## Discussion

The user chose agent-drafted translations for the languages ANALYSIS L10n
v1.0 §4 suggests, one fresh agent per language in its own worktree, each
followed by a fresh reviewer; Weblate may take the `.po` files over later.

## Analysis

- Languages: fr, es, it, nl, pt_BR, zh_CN, ja, pl.
- Plural forms follow Nextcloud's `core/l10n/<lang>.json`: fr, es, it,
  pt_BR 3; nl 2; zh_CN, ja 1; pl 4.
- The store's manifest schema knows fr, es, it, nl, ja, pl, and `pt-br` and
  `zh-hans` for pt_BR and zh_CN.
- `l10n.sh add` rewrites the template, so languages are started in separate
  worktrees, never in parallel in one tree.

## Implementation Plan

1. **Translate** (agents, worktrees): `add <lang>`, fill all 359 texts, a
   `GLOSSARY.md` marked unreviewed, manifest summary and description in the
   report; `update`, `build`, `check` pass in the worktree. Results copied
   to the scratchpad. Rolling: four at a time.
   **Verification:** `check` complete for the language, `msgfmt --check`,
   placeholders identical.
2. **Review** (agent per language, after its translation): reads the draft
   against the glossary, Nextcloud's own terms and the source; lists doubts,
   edits nothing.
   **Verification:** a report per language.
3. **Gate** with the user: the review findings, which languages ship.
4. **Integrate** (once the tree is free): copy the files in, `update`,
   `build`, `check`; `info.xml` entries; CHANGELOG; one commit per language.
   **Verification:** `check`, the manifest schema, Vitest.

## Proposed commit messages

`[TASK] <Language> translation, an unreviewed draft`, one per language;
each in full at its gate.
