# NOTE Nc35 v1.1: what step 1 measured

Measured 2026-10-01 on harness instance 35 (Nextcloud 35.0.1, PHP 8.3.33),
released from `nc_metadata` and mounted with this app at `5352a11`. The app
was enabled with `--force`, since `info.xml` still says `max-version="34"`.

## Passing

- **Enable:** the migration and the repair steps run clean.
- **Unit:** 1000/1000.
- **Integration:** 101 of 105 pass.
- **e2e:** six specs, 40/40: `checksums`, `duplicates`, `l10n-german`,
  `rules-personal`, `status` and `sudo-tokens`.
- **The search provider:** `file_checksum_search_provider` ("File
  checksums") is registered in `/ocs/v2.php/search/providers`.
- **Rector, `NEXTCLOUD_33` set:** no system errors; one rule
  (`ReplaceFetchAllMethodCallRector`) over 8 files.

## API, read from the 34 and 35 source trees

Every OCP class the app imports (84) was compared by signature.

- **Nothing removed or newly deprecated.** The changes add return types,
  to interfaces the app does not implement.
- **`ISchemaWrapper::getTable()`** returns `OCP\DB\Schema\ITable`, no longer
  Doctrine's `Table`. The app's one migration calls only `hasIndex()` and
  `addIndex()`, which `ITable` has with compatible signatures. Its `@var
  Table` docblock is wrong on 35.
- **Symfony Console** goes from 6.4 to 7.4. Every command already declares
  `execute(): int` and `configure(): void`.

## What failed, and why

1. **Integration, `testMetadataOfADeletedUserIsSweptUp`.** Nextcloud 35
   deletes a removed storage's metadata with its filecache rows
   (`Storage::removeFileCacheEntries()`, nextcloud/server#63998, backports
   to 34 and 33 asked for). The test's premise, that deletion leaves the
   metadata behind, no longer held. Fixed in `dcae760`: the test makes its
   own orphan.
2. **Integration, three `FileLocationIntegrationTest` cases skipped.**
   `groupfolders` has no release for 35 on the app store yet
   (`app:install` reports it not found), so the team-folder cases cannot
   run. External; they run once groupfolders ships for 35.
3. **e2e, `global-search.cy.js`.** Nextcloud 35's header search is a field
   ("Apps, files, messages, and more", Ctrl K), not the
   `.unified-search-menu button` the spec clicks. The provider itself is
   there (above). The spec needs a way in that works on 33, 34 and 35.
4. **e2e, `rules-admin.cy.js`, "a placeholder row seeds the dialog".**
   Placeholder rows come only from external storages and team folders
   (`RuleTable.vue`, `namespaces`). Instance 35 has neither, since
   `files_external` is disabled and groupfolders is absent, so there is
   none to click. On 34, groupfolders provides one. The spec assumes a
   namespace it does not create.
5. **e2e, `app-enable.cy.js`.** It disables the app and enables it through
   the Apps page, which refuses an app whose `max-version` is below the
   server. It then left the app disabled, and every spec run after it
   failed on that. Step 3's `max-version="35"` is what this needs. A first
   e2e run that included it is discarded for that reason.
