## What re-verification changed

**Both Block 0 findings are real, and both are worse than v1.0 said.**

1. `MetadataService::parseQueryTerm()` (`:3112`) matches the algorithm prefix
   with `[a-zA-F0-9]+` — `a-z`, `A-F`, digits. No hyphen. So `sha3-256:<hash>`
   and `sha3-512:<hash>` are rejected, and both are in the shipped default
   allowlist; an uppercase `SHA256:<hash>` is rejected too. This is the parser
   behind the unified-search provider (`HashSearchProvider.php:87`) and
   `occ fcias:search` (`SearchHash.php:71`), so the failure is user-visible in
   both: the term parses as "not a hash" and the search returns nothing.
   Not a typo to document — a defect to fix.
2. `HashCalculationService::recalcAllExistingAlgos()` (`:767`) is broken for
   the only case it exists for. `getHashes()` returns `algo => hash`
   (`MetadataService.php:155`); the method passes `array_values()` of it —
   the *hashes* — to `recalcHashes()` as algorithm names, and iterates the map
   by value, so `$batch['results'][$algo]` never hits. `recalcHashes()`
   validates (`:837`), so every entry fails with "Unsupported algorithm:
   <hash>" and `processed` is always 0. Its unit test passes only because the
   mock returns a **list** where the real collaborator returns a **map**
   (`HashCalculationServiceTest.php:838-847`) — the test pins a shape that
   does not exist. Fixing the mock is the more valuable half.
   Note: the method has **no production caller** — `HashIndexService:67`
   forwards it and nothing calls that. See Open decisions.

## Blocks

**0a `[FIX]` — the search term parser accepts every name the catalogue can
produce.** `[a-zA-Z0-9-]+` for the algorithm prefix, matching
`AlgorithmCatalogue::NAME_PATTERN` case-insensitively. Unit tests for
`sha3-256:`, `sha3-512:`, `SHA256:`, and a hyphenated name that is not an
algorithm (still parses as a term; validity is the catalogue's business, not
the parser's). `### Fixed` bullet — the defect is in 0.19.0.

**0b `[FIX]` — recalculating every existing algorithm uses their names.**
`array_keys()`, iterate the keys, return a list of algorithm names in `algos`
for both branches. Rewrite the test's `getHashes()` mock to the real
`algo => hash` shape, so the test would have failed. `### Fixed` bullet.

**1 `[CLEANUP]` — prose that contradicts the code.** The 12 lib items and the
7 src items, plus deleting the dead `lockScope` path in `RuleForm.vue`: the
prop is passed by no caller and its five template branches carry the retired
"User Scope" vocabulary. User-visible strings: none of the survivors are
user-visible, and no spec pins the help text.

**2 `[CLEANUP]` — the public surface's annotations.** `ChecksumApi`
(`getHashesByPath` shape, `recalcHash`'s real keys incl. the `fileid` that is
never returned, `findByHash`'s `@throws`), `FilecacheService`
(`getUserFolderPath`'s non-existent exception class, plus the missing
`declare(strict_types=1)` and header), `HashCalculationService`
(`recalcFileHash`'s `locked`/`error`, `recalcHash`'s absent `@return`),
`MetadataService` (nine methods missing `@throws \OCP\DB\Exception`;
`getAlgorithmenFromKey` typed `mixed`→`mixed` for what is always
`string`→`string`), `RuleService` (`applyRule`'s `@throws`, `ruleAdd`'s
`@return`).

**3 `[CLEANUP]` — the missing docblocks**, reasoning-first: the by-reference
`getHashes()` nobody binds by reference, `clearMetadata()`'s silently forced
`$save`, `setHashes()`'s `$keepAdditional` merge and silent overflow drop,
`acquireLock()`'s `false`-means-skip, `collectFilesForUser()`'s in/out
accumulators and "batch size 0 means unlimited", `getNodeById()`'s throw,
`HashSearchProvider`'s limit-after-authorisation contract, `Selector`'s
round-trip invariant. A docblock that would only restate the signature is
left off.

**4 `[CLEANUP]` — restatement deleted.** Six command classes' configure/execute

## Open decisions

- `recalcAllExistingAlgos()` has no caller. Fixed here rather than deleted,
  because deleting a facade method is the larger call; say if it should go.
- `ListRules` numbers positions per band, the pages per segment. The comment
  is corrected to say so. Aligning the CLI to the pages would change output
  scripts may read, so it is not done here.
- `getAlgorithmenFromKey` is misspelled, `public static`, three call sites,
  not part of `lib/Public/`. Renamed to `algorithmFromKey` in Block 2 unless
  you want the name kept.
