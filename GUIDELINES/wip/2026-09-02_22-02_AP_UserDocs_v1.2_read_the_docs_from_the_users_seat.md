# AP UserDocs v1.2: read the docs from the user's seat

> **Status: preliminary — not yet approved.** Follows v1.1 (retired), which
> corrected what the docs *claimed*. This pass compares what they *describe*
> with what the screen shows, before AP Screenshots fixes those screens in
> pictures. Where the mismatch is the screen's fault, the screen changes first
> and the sentence follows — which is why this precedes Screenshots even at the
> cost of touching some sentences twice.

## Discussion

`docs/user-guide.md` is not only a document: the Duplicates page and the
personal settings page render it as their Help tab (`DocsViewer
only="docs/user-guide.md"`). So a sentence describing a control the user does
not see is a UI defect in its own right, shown on the same page as the control.

Every finding below was checked against the current templates, not remembered.

## Analysis

### A. Where the screen is wrong and the sentence is right

| Screen | Now | Finding |
|---|---|---|
| Duplicates: algorithm filter | `<select class="db-select">` with no label; first option reads *All algorithms* | The guide calls it **Algorithm** because a filter needs a name; the control has none — a reader cannot match the sentence to the box, and a screen reader announces an unlabelled select. |
| Duplicates: algorithm filter | seven options; `adler32` missing | The backend supports eight (`HashCalculationService.php:38`), the FAQ lists eight, rules can compute `adler32`. A file hashed with it cannot be browsed for duplicates. |
| Sidebar: Recalculate section | two quick buttons **SHA-1** / **MD5**, a picker, and a button labelled **Recalc** | *Recalc* abbreviates the section title above it. The guide, rightly, never uses the abbreviation. |
| Unified search | provider `getName()` = **File Checksums** | The guide says "pick the **File Checksum Index & Search** result". One of the two has to move; the app's own name is on every other surface. |

### B. Where the sentence is wrong or silent and the screen is right

| Doc | Says | Screen |
|---|---|---|
| guide §duplicate browser | describes six controls | also a **Help** tab, **← Previous / Next →** paging, and two empty states (*No duplicate files found.* / *No matching duplicate files found.*) |
| guide §duplicate browser | "links that open each file in the Files app" | they open in a **new tab** (`target="_blank"`) |
| guide §file detail pane | "A **Recalculate** action" | three sections — **Checksums**, **Recalculate**, **Duplicates** — the second with SHA-1 and MD5 one-click buttons plus a picker for the rest, the third with a **Find duplicates** button that unfolds results in place |
| guide §file detail pane | "reports that the file is excluded" | the actual sentence: *Hashing is excluded for this path by an administrator rule.* Quote it, so a user can search for it. |
| guide §your hashing rules | "Open Personal settings → File Checksum Index & Search" | the page has two tabs, **Rules** and **Help** — and Help is this guide. The guide never says so; README and FAQ do. |
| README §Admin & Personal Settings | "the eroded count" | the row is **Untrusted Hashes**, eroded and reset together, since the RuleBands cycle |
| README §Duplicate File Browser | seven algorithms | same as A.2: matches the screen, contradicts the backend and the FAQ |

Verified and left alone: the rate limit of 20 per minute (`#[UserRateLimit(limit: 20, period: 60)]`), *Read-only* in place of the menu, the **i** buttons on every column header, band headers, the pen and the ⋯ menu, the Type table, the drag rules, the "no keyboard equivalent" admission, "16 CLI commands" (`info.xml` has 16), the Documentation table.

### C. Not a doc question

The sidebar's quick buttons are hard-wired to SHA-1 and MD5 whatever the rules
compute. A user whose rules produce SHA-256 gets two buttons for algorithms
nothing else on the instance uses, and the one they want is behind the picker.
Raised here because the guide would otherwise document the wrong default;
decided in **Open decisions**, not here.

## Open decisions

1. **Search result name.** *File Checksums* (short, what the results are) or
   *File Checksum Index & Search* (the app's name everywhere else)? The plan
   assumes the app's name, for one vocabulary; the shorter one is defensible.
2. **Sidebar quick buttons.** Keep SHA-1/MD5 fixed; or derive the two from the
   algorithms the file's governing rule computes, falling back to SHA-1/MD5 when
   no rule governs it. The second is the better product and a larger change;
   the guide's wording depends on which.
