# AP EtagStamp v1.3: Hashes vouched by ETag

## TL;DR

v1.1's five blocks are in. A review found the write side still judging
freshness by the mtime alone, the duplicates and a file's own route outside
the ETag rule, a NULL filecache ETag nobody walks, and docs behind the
code. v1.3 adds the blocks that fix them; Oracle is stated unsupported.

- Hashing, recalculation, publishing: `stamp >= mtime` → also `vouches()`,
  the read side's rule; a moved ETag is outdated
- NULL `fc.etag` under an ETag stamp → unvouched, and walked
- Oracle → unsupported, as `info.xml` already enforces; README says so
- Duplicates, `/file/{id}/duplicates` → vouched files only
- `/file/{id}/hashes` → one vouched value; `mimetype` null with the hashes;
  under `stat`, `{}` for none, `null` for stale or reset
- Walks → the daily one waits for `etag-stamp`; adoption queues in the
  rule's mode; one stats slot per walk
- `/hashes/missing` → canonical for sudoers; empty windows skipped; a
  home storage's files area only
- CHANGELOG: the narrowing under Changed; docs level with the code
- Import (optional) → a record's ETag, stamped where it is the file's
  present one

## Discussion

A review of v0.25.0..HEAD, read-only, ranked its findings; this plan takes
the unreleased ones (H1, H2, M1–M8 and the lows), each checked against the
code. The 0.25.0 findings are AP ReviewFixes v1.0's, which runs after this
one. Decided at the gates and since:

- **v1.1's NOTE was wrong about recalculation.** It said a recalculation
  returns what it has just read. `isHashUpToDate()` kept `stamp >= mtime`
  alone, so `missing` mode, `auto` and the recalc routes kept hashes whose
  ETag had moved, and stamped the new ETag over them: the lookup then
  returned the old content's hashes as valid. Block 6 makes the write side
  judge as the read side does.
- **Oracle is not supported** (v1.3). `appinfo/info.xml` declares
  `sqlite`, `mysql` and `pgsql`, and Nextcloud refuses to enable the app
  elsewhere; the README's "any database supported by Nextcloud" says
  otherwise and is corrected. No query is made slower or clumsier on the
  three for Oracle's sake. Should Oracle be asked for, it is work of its
  own: `expr()->nonEmptyString()` gives today's SQL on the three and
  `IS NOT NULL` on Oracle, `queryDuplicates()`'s `MAX()` over the JSON
  column needs another form, and CI would run Nextcloud's own Oracle job
  (`phpunit-oci.yml`). v1.2's Oracle rewrite of three queries is dropped.
- **Imported hashes keep today's behaviour (M5).** They carry no ETag, are
  held by the mtime rule as a legacy stamp is, report the filecache's
  `etag` under `stat`, and adoption gives them that one later. Block 11
  documents it.
- **Block 13 is optional: an import that carries the ETag.** An export
  record gains the ETag its hashes were stamped with. An import stamps it
  only where it equals the file's present ETag, which is a restore onto
  the same unchanged file, and otherwise does what it does today. Across
  instances ETags never match, so nothing changes there. CSV is read by
  header and JSON by key, so an older import ignores the new field.
  Recommended: it closes the mtime hole for the commonest restore, at the
  cost of one column.
- **The narrowing is Changed (M6).** Below 1.0.0 a break ships in a minor
  under Changed, saying what a caller has to change (`docs/api-v1.md`,
  *What Constitutes a Breaking Change?*). The restoring parameter the
  table asks for binds from 1.0.0 on.
- **A reset file's hashes under `stat` (M2)** - a file whose hashes
  `occ fcias:reset --hashes` revoked, `stale:reset`, which the code calls
  disowned - are null, as the listing has them. Without `stat`,
  `/file/{id}/hashes` shows them as 0.25.0 did: the per-file read shows
  what is stored (`andWhereNotStale()`).
- **A stale entry's `updated_at` under `stat`** is null with its hashes
  and `etag`: it is when those hashes were stamped. Without `stat`
  nothing changes.
- **Kept, with the reason:**
  - `withIgnored` and `withExcluded` beside `unmatched`: named in v1.1 and
    approved there.
  - `FileListener::onWrite()` beside `RuleService::contentChanged()`: the
    listener clears a `force` or `lazy` file at once, the walk leaves it to
    the drain (NOTE v1.1); one method with a flag would hide that.
  - `findByHash()` judging in SQL, then again under `stat`: a write between
    the two gives a hash with `etag: null`, which is true by then.
  - `createTestFile()` in eight test classes: older than this plan.
- **One stats slot per walk** gives the admin page two job names more,
  translated into the eleven kept languages; their summaries reuse texts
  that are translated already.

## Analysis

Checked against HEAD:

- **H1.** `HashCalculationService::isHashUpToDate()` is `stamp >= mtime`.
  `isOutdated()`, `asTheQueueWould()`, `recalcHashes()` (skip-existing and
  the MIME-alone read) and `processMimeType()` go through it.
  `MetadataService::isCurrent()` is the same test, and decides what is
  published in `saveMetadata()`, `writeHashes()` (twice), the index
  rebuild and `backfillHashes()`. `vouches()` is the read side's rule in
  PHP; `FilecacheService::stateOf()` reads `etag`, `mtime` and
  `storage_mtime` by primary key.
- **Oracle.** `unvouchedCondition()`, `exportStates()` and
  `FilecacheService::pageFileidChecksums()` compare with `''`, which
  Oracle binds as NULL; on Oracle each would match nothing. Oracle is not
  a supported backend (`info.xml`), and no CI job runs it.
- **A NULL `fc.etag`** under an ETag stamp satisfies neither
  `vouchedCondition()` nor `unvouchedCondition()`: the file is hidden and
  never walked. PHP casts it to `''`, unvouched.
- **M1.** `queryDuplicates()` applies `andWhereNotStale()` only;
  `ChecksumApi::findSameHash()` takes the reference hashes from
  `listedHashes()` unchecked.
- **M2.** `getHashesByFileId()` reads the stamp row in `getUpdatedAt()`,
  in `isVouched()` and under `stat` in `withStates()`; `withMimeTypes()`
  runs before the vouched check.
- **M3.** `RuleProcessingJob::queueStampCheckIfDue()` is due at once on a
  first run, beside the `etag-stamp` walk the upgrade queued. The
  filecache walk erodes or requeues legacy rows adoption would keep.
- **M4.** `HashListingService::missingPage()` calls `seenThrough()`
  without `! $canonical`.
- **The missing route** reads a window of 10,000 file ids, so sparse ids
  give runs of empty pages. `andWhereGoverned()` leaves out
  `files_trashbin/`, `files_versions/` and `appdata_`; a home storage's
  `uploads/` and `cache/` pass, and the instance-wide twin with
  `unmatched=1` would list them.
- **The walks.** `StampCheck` records its three walks under one
  `JOB_STAMP_CHECK`. `adoptEtag()` queues `pending:auto` whatever the rule
  says. `queueChangedAfter()` calls `contentChanged()`, which resolves a
  rule per file, where `governingRulesForFileIds()` resolves a page.
- **Docs.** `docs/FAQ.md` *What am I looking at in the database?* says the
  stamp row's string is empty, that Nextcloud rewrites the row, and that
  a state row's int is 0. `docs/api-v1.md` *File state* says the answers
  without `stat` are "as they were" and does not list `listMissing()`; the
  cross-account section says seven twins; the rate-limit table lacks the
  missing route. The OpenAPI missing routes reuse `HashListAlgo` and
  `HashListAfter`, and two `nullable` sit beside an `allOf` without a
  `type`. README: "five paths", "one piece of housekeeping". The
  docblocks of `writeState()` and `syncMimeTypeRow()` describe the old
  writes.

## Implementation Plan

### Block 6: Hashing judges freshness as the read side does

1. `MetadataService::isCurrent(IFilesMetadata $metadata, ?array $state)`:
   `stamp > 0`, `stamp >= mtime` and `vouches()` against the state's
   `etag` and `storageMtime`. The state comes from
   `FilecacheService::stateOf()`; `pageFileidChecksums()` reads
   `storage_mtime` for the backfill.
2. `HashCalculationService::isHashUpToDate()` delegates to it, the state
   read once per file.
3. A moved ETag makes the document outdated: `keepOnly()` drops the
   algorithms not recomputed, and every kept one is read again. `auto`
   reads where it would only have moved the stamp.
4. CHANGELOG: none; the bullet Block 8 moves to Changed covers it.

**Verification:** integration, `VouchedByEtagTest`: with the ETag moved by
hand and the mtime kept, `recalcHash` answers `existed: false` and stamps
the new ETag; `missing` with an algorithm added reads the old one again;
`auto` reads a legacy stamp below `storage_mtime`. Unit: `isOutdated()` on
an ETag mismatch. Both suites on 33 and 34, ECS, Psalm, `changelog.sh
check`.

### Block 7: A NULL filecache ETag; Oracle stated unsupported

1. `unvouchedCondition()`: an ETag stamp against a NULL `fc.etag` is
   unvouched. The comparisons with `''` stay as they are.
2. README *Requirements*: SQLite, MySQL or MariaDB, PostgreSQL; Oracle is
   not supported.
3. CHANGELOG: none; the bullet Block 8 moves to Changed covers the first,
   and the README is not shipped.

**Verification:** integration: a file whose filecache ETag is set NULL is
walked and queued. Both suites, lint, `changelog.sh check`.

### Block 8: Duplicates and a file's own route by the vouched rule

1. `queryDuplicates()`: the stamp row and the filecache joined,
   `vouchedCondition()` applied. The Duplicates page's query is timed on
   the harness before and after.
2. `findSameHash()`: a reference file not vouched has no duplicates.
3. `getHashesByFileId()`: one read of the file's state, its marker and its
   document; `vouched` decided once; `mimetype` null where not vouched.
   Under `stat`: `hashes` null where stale or reset, `{}` where the
   document holds none; `updated_at` and `etag` null with them. The
   listing's stale entries get a null `updated_at` too.
4. `docs/api-v1.md` *File state*, `docs/api-v1-openapi.yaml`.
5. CHANGELOG: the Fixed bullet moves to Changed (draft):
   `- README.md, *When hashes go away*: a file changed without the app`
   `  hearing of it leaves the lookup, the listing, the duplicates and its`
   `  own hashes until hashed again; ?stat=1 names it.`

**Verification:** integration: an ETag moved by hand takes the file out
of `/duplicates`, `/sudo/duplicates` and `/file/{id}/duplicates`;
`/file/{id}/hashes` without `stat` gives `{}` and no `mimetype`, and with
it `null`; a reset file gives its hashes without `stat` and `null` with
it; a never-hashed file gives `{}`. Both suites, lint, check.

### Block 9: The walks

1. `queueStampCheckIfDue()` does not queue the daily walk while the
   `etag-stamp` walk is queued, and leaves the clock alone. A daily walk
   that finds it queued does nothing and zeroes `stamp_check_last_queued`,
   so the first tick after it queues the walk again.
2. `adoptEtag()` queues in the governing rule's mode, through a helper
   that gives a file's queue mode from its rule; ReviewFixes reuses it.
3. `queueChangedAfter()` resolves the rules a page at a time.
4. One stats slot per walk: `stamp_check`, `stamp_check_etag`,
   `stamp_check_filecache`. The admin page names the two new ones, with
   `TRANSLATORS` comments; the ETag walk's summary reuses
   *stamped, queued again*, the filecache walk's *queued*.
   `scripts/l10n.sh update`, the eleven languages, `build`; `js/` rebuilt.
5. `docs/FAQ.md`, the background jobs: the stamp check and its walks.
6. CHANGELOG: none; the bullets already in place describe the result, and
   the commit says so.

**Verification:** unit: `RuleProcessingJobTest` (held while the ETag walk
is queued), `StampCheckTest` (the deferral; a slot per walk); integration:
adoption queues in a `missing` rule's mode. `npm test`, `npm run lint`,
`npm run typecheck`, `scripts/l10n.sh check`; both suites, lint.

### Block 10: `/hashes/missing`

1. `ChecksumApi::listMissing()` takes `$canonical`, as `listHashes()`
   does, and `missingPage()` hands `seenThrough()` its negation; the
   `/sudo/` twin passes `readsCanonically()`.
2. A window starts at the first file id after `after`, one indexed
   `MIN()`, so a gap in the ids costs one page, not one per 10,000.
3. The files area: an integration fixture puts a file under a home
   storage's `uploads/`; if `/sudo/hashes/missing?unmatched=1` lists it,
   a home storage is kept to `files/` on this route.
4. `docs/api-v1.md`: the twin's locations; the window.
5. CHANGELOG: none; the Added bullet stands.

**Verification:** `MissingHashesTest`: a sudoer naming `users[]` reads own
addresses on both twins; the `uploads/` fixture is in neither listing.
Unit: the window start after a gap. Both suites, lint, check.

### Block 11: Docs and CHANGELOG

1. `docs/api-v1.md` *File state* and README: a stamp without an ETag,
   from before the upgrade or an import, is held by the mtime rule, and
   `etag` is then the filecache's. "Without it, the answers are as they
   were" gives way to what changed by default.
2. `docs/FAQ.md` *What am I looking at in the database?*: the stamp row's
   string is the ETag and the app writes the row; `file-checksum-etag`;
   the state row's int counts failed attempts.
3. `docs/api-v1-openapi.yaml`: the missing routes' own `algo` and `after`;
   `type` beside each `nullable` on an `allOf`.
4. `docs/api-v1.md`: the cross-account section counts the twins and the
   rate-limit table names the missing route and its twin; *File state*
   lists `listMissing()` and its route; a file with hash rows and no stamp
   row is in neither listing until `missing-stamps` has run. README: the
   paths and the housekeeping counted again for the daily walk.
5. Docblocks of `writeState()` and `syncMimeTypeRow()`.
6. CHANGELOG (drafts):
   Added `- stamp_check_interval (README.md, *When hashes go away*): how`
   `  often the walk for files changed unheard runs; a day by default.`
   Changed, reworded: `- MetadataService::setSelfIndexed(): the writer for`
   `  a file's own index rows, cut to 63 characters in one place.`

**Verification:** `changelog.sh check`; the OpenAPI document lints; every
link and anchor resolves.

### Block 12: Duplicated code made one

1. `fetchEtaglessStampIds()` through `withoutEtag()`; `stateOf()` through
   `statesOf()`; the three null-state arrays in `ChecksumApi` as one;
   `deleteState()` through `unsetSelfIndexed()`.
2. `missingPage()` and `entries()` share the path, owner and location
   code; `pageUnhashedFiles()` and `whereListed()` the hash-count
   subquery.
3. Tests: `etagMovesOn()` once, in a trait.
4. CHANGELOG: none, no behaviour changes; the commit says so.

**Verification:** both suites on 33 and 34 unchanged in outcome; lint.

### Block 13 (optional): An import carries the ETag

1. `HashRecord` gains `?string $etag`; CSV a column `etag`, JSON a key;
   the sum format none.
2. `exportHashes()` yields the document's ETag, and the export writes it.
3. `ImportService`: a record's ETag equal to the file's present one
   (`locateAllByPath()` reads it) is stamped with the hashes; any other,
   or none, imports as today.
4. README, export and import; `occ fcias:import`'s help.
5. CHANGELOG, Added (draft):
   `- occ fcias:export, fcias:import: a hash carries its ETag, and its`
   `  restore onto the unchanged file is vouched for by it.`

**Verification:** integration: export, wipe the metadata, import: the stamp
row carries the ETag; with the file changed in between, none; a CSV
without the column imports as before. Both suites, lint, check.
